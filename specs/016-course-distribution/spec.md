# Feature Specification: 课程分销方案

**Feature Branch**: `[016-course-distribution]`

**Created**: 2026-09-06

**Status**: Draft

**Input**: User description: "为课程分享做分销方案,即学员分享课程给用户,用户注册之后购买一样的课程返还佣金,对应的返还需要有后台的配置,且只能是直系注册的用户才能返还,且不能超过 3 级分销,因为在我国超过三级分销就是违法了."

**前置规格**: `001-personal-learning-site`（学员、课程访问权、购买订单、价格模式、激活码、收件箱消息）；`009-learner-coupons`（满减与上下限的可配置规则的写法风格）；`010-course-notify-feedback-codes`（消息类型与投递约定）；`014-ops-exception-inbox`（管理员与管理员操作记录风格）；`015-course-publish-checklist`（核验清单的影响栏写法风格，复用为分销核验结果）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 学员生成只属于自己的专属分享链接 (Priority: P1)

作为已登录学员, 我可以为任何「已发布」的课程生成一条带本人推荐人标识的专属分享入口 (同一学员可持有多条, 可撤销; 明文短码仅生成当时返回一次). 该入口本身不可推断其他学员身份, 也不暴露管理端配置. 任何人(访客或学员)经由此入口访问课程详情页时, 浏览器看到的页面与普通访问一致, 只是后台悄悄记下了「这次访问由某学员推荐, 但尚未与任何账户绑定」. 推荐关系只在该访客随后用**新手机号**完成学员注册并验证成功后, 才被确认为有效, 写入学员的「推荐人」字段, 并触发分销事件; 老学员、已注册但未访问、重复访问等情况都不会改变推荐关系.

**Why this priority**: 没有分享入口和推荐人绑定, 后续分销判定与佣金计算无从谈起. 这是最小可交付切片.

**Independent Test**: 用学员 A 生成的链接打开未登录访客视角的课程详情页 → 没有任何学员身份信息泄露. 让该访客用未注册的手机号完成注册验证 → 新学员档案出现推荐人 = A. 让同一访客换浏览器再访问一次 → 推荐人不变, 仍是首次绑定. 让另一名老学员 B 经此链接打开 → B 的档案不会写入推荐人, 也不影响 A 的待结算佣金.

**Acceptance Scenarios**:

1. **Given** 学员 A 已登录且目标课程处于「已发布」, **When** A 在课程详情页生成分享入口, **Then** 系统为 A 颁发一条带短随机串的分享链接, 仅在分享当时返回一次明文, 之后所有列表与详情只显示脱敏形态 (前 4 后 4).
2. **Given** 学员 A 生成了分享链接, **When** 任意未登录访客点开链接访问课程详情页, **Then** 页面与普通访问无差别, 不会显示「A 推荐」, 也不会显示 A 的昵称或头像; 后台只记一条「未绑定」的访问痕迹.
3. **Given** 访客经由 A 的分享链接访问后, 用一个**未注册过**的手机号完成学员注册, **When** 注册成功, **Then** 该新学员的「推荐人」字段被设为 A, 写入时间取注册完成时刻, 后续该学员的所有学习端会话都带推荐人 = A.
4. **Given** 老学员 B 已存在档案, **When** B 在已登录态点开 A 的分享链接, **Then** B 的档案「推荐人」字段保持为空 (若原本为空), 也不会被覆盖; A 的待结算佣金不因 B 的访问而增加, 因为 B 不是新注册.
5. **Given** 访客在同一分享链接上先后用两个不同未注册手机号完成注册, **When** 第二个注册也成功, **Then** 只有第一个注册获得推荐人 = A, 第二个注册因「已被另一注册先绑定」而没有推荐人, 且 A 的「待结算新学员」数仅记第一个.
6. **Given** 学员 A 在另一台设备再次打开「我的分享」列表, **When** 查看自己的分享入口, **Then** 看到该入口的脱敏形态、生成时间、累计访问人次、累计已绑定新学员数; 明文链接不再重新展示.

### User Story 2 - 管理员配置分销规则与级别上限 (Priority: P1)

作为具备分销配置权限的管理员, 我在管理端设置整个站点的分销规则: 是否开启分销、佣金比例 (按课程或全局)、佣金计算基数、结算上限 (单笔 / 单课程 / 单学员 / 全站)、是否允许学员查看佣金明细、级别上限 (1–3). 首版发放形态固定为「仅记账」, 结算周期固定为「订单成功且退款期结束」, 退款撤销固定为「全部撤销」. 同时, 我可以为某一门课程覆盖佣金比例, 或为某一课程关闭分销. 配置即时生效, 但已发生的佣金快照不可被新配置改写.

**Why this priority**: 没有后台配置, 佣金计算、发不发、发给谁全部没有依据. 用户明确要求「后台配置」是分销的前提.

**Independent Test**: 把分销从「关」切到「开」并设置佣金比例 10% / 单笔封顶 50 元 / 单学员每课程累计封顶 200 元 / 结算周期 = 订单成功且退款期结束 → 用一笔 600 元订单触发 → 待结算佣金 = min(60, 50) = 50. 再做一笔 300 元订单 → 待结算佣金 = 30. 改全局佣金比例到 20%, 已产生的两条待结算记录金额不变. 把某课程开关关掉后, 之后该课产生的订单不再进佣金计算.

**Acceptance Scenarios**:

1. **Given** 管理员在分销配置页把开关由「关」改「开」并填入合法参数, **When** 保存, **Then** 站点进入分销开启态, 学习端学员开始看到分享入口, 配置变更时间与操作者写入审计.
2. **Given** 全局佣金比例已设为 P, 单笔封顶为 C_max, **When** 一笔订单成功且完成退款期, **Then** 该笔订单对每个合格推荐人的佣金 = min(订单实付 × P, C_max), 写入「待结算佣金」并按订单快照记录, 后续调整 P 或 C_max 不改写该快照.
3. **Given** 管理员把单学员每课程累计封顶设为 X, **When** 同一推荐人在同一课程下累计触发佣金将超过 X, **Then** 超出部分在该次结算时被截断为 0, 并不补发; X 的变更只影响变更后发生的新订单.
4. **Given** 管理员为某课程设置「关闭分销」, **When** 该课程产生新的已结算订单, **Then** 该订单不产生任何佣金记录, 既不写待结算也不写已结算; 关闭前的已存在佣金快照不受影响.
5. **Given** 管理员为某课程覆盖佣金比例为 P_course, **When** 该课程产生已结算订单, **Then** 该课程的佣金按 P_course 计算, 全局 P 不再叠加; 同一订单不得被两种比例重复计算.
6. **Given** 管理员把「结算周期」设为「订单成功且退款期结束」, **When** 一笔订单处于「成功但仍在退款窗口内」状态, **Then** 该订单暂时不产生佣金, 退款窗口结束且无退款时再结算; 若发生退款, 该订单对应佣金全部撤销, 关联推荐人的待结算 / 已结算金额同步扣减.
7. **Given** 管理员试图把佣金发放形态改为「站内余额」, **When** 保存, **Then** 系统拒绝保存并提示首版不挂入学员钱包; 发放形态固定为「仅记账」.

### User Story 3 - 直系注册链路只向上返三级 (Priority: P1)

作为系统, 我在学员 A 推荐学员 B 注册之后, 当 B 任意一笔订单成功并完成退款窗口后, 我向 A 发一笔「一级」佣金; 当 B 也推荐 C 注册、C 任意一笔订单同样结算时, 我向 B 发一级佣金, 并向 A 发「二级」佣金; 当 C 推荐 D、D 结算时, 我向 C 发一级、向 B 发二级、向 A 发三级. 当 D 再推荐 E、E 结算时, 只向距 E 最近的最多 3 名祖先发佣金 (一级 C, 二级 B, 三级 A); D 与更远的推荐人不拿. 任意一笔订单的佣金接收人最多 3 个, 且总佣金不得超过该订单单笔封顶. 佣金按每笔成功订单计算, 不以「该课首单」为条件.

**Why this priority**: 用户明确指出「只能是直系注册的用户」「不能超过 3 级分销」, 且说明这是合规硬约束 (我国法规). 这是本规格的合规主线.

**Independent Test**: 构造 A→B→C→D→E 五级注册链. E 购买某课 → 仅有 C、B、A 拿到佣金 (按 1/2/3 级递减规则), D 不拿, 也不再向上追. 再构造 A→B 与 F→G 两条独立链 → 互不影响. 再构造跨链测试: A 推荐 B, F 推荐 B 的家人手机号 (新注册) — 后者使用 F 作推荐人, 不会污染 A 的链路. 验证总佣金 ≤ 单笔封顶, 三个接收人级别序号连续且总人数 ≤ 3.

**Acceptance Scenarios**:

1. **Given** 推荐链路 A → B → C → D, 链路深度为 3, **When** D 任意一笔订单成功并完成退款窗口, **Then** 佣金按级别下发: C 拿「一级」佣金, B 拿「二级」佣金, A 拿「三级」佣金; 总人数 = 3, 任何人不得重复领取.
2. **Given** 推荐链路 A → B → C → D → E, 链路深度 ≥ 4, **When** E 任意一笔订单成功并完成退款窗口, **Then** C、B、A 各拿对应级别佣金 (链路中靠 E 最近的三人), D 与 A 之上 (若有) 一律不拿; 总接收人数仍为 3.
3. **Given** A 推荐 B, F 推荐 G, 两条链路互不相交, **When** B 与 G 各自一笔订单完成结算, **Then** A 仅因 B 触发而拿佣金, 不因 G 拿佣金; F 仅因 G 拿佣金, 不因 B 拿佣金.
4. **Given** A 推荐 B, B 推荐 C, B 推荐 D, 形成 C 与 D 都是 A 的「孙子」, **When** C 与 D 各自一笔订单完成结算, **Then** A 因 C 与 D 各拿一笔「二级」佣金, B 因 C 与 D 各拿一笔「一级」佣金; A 与 B 在同一笔订单中级别与金额分别独立计算, 不会因为重复出现而被合并或升级.
5. **Given** B 已注册但尚未推荐任何人, A 也不是 B 的推荐人, **When** B 一笔订单完成结算, **Then** B 此次结算没有上游推荐人, 不产生任何佣金记录, 也不会追溯到任何与 B 同名 / 同手机的「假定推荐人」.
6. **Given** 管理员试图把站点级别上限调为 4, **When** 保存, **Then** 系统拒绝保存并提示「级别上限不可超过 3, 这是合规硬约束」; 任何管理员 (含超级管理员) 均不得解除该上限.
7. **Given** 某笔已产生佣金的订单发生退款, **When** 退款成功, **Then** 该订单触发的全部佣金记录变为已撤销; 系统不为下级订单追溯扣减, 也不引入独立的「已占用」余额字段.

### User Story 4 - 学员查看我的佣金与分享效果 (Priority: P2)

作为分销参与者, 我在学习端看到三块信息: (1) 我的分享链接列表 (脱敏) 与累计访问人次、累计已绑定新学员数; (2) 我的佣金总览: 待结算 / 已结算 / 已撤销 / 累计, 以及最近若干条记录 (时间、课程、被推荐人脱敏手机号、级别、金额); (3) 我的下级链快照: 我直接推荐了谁 (脱敏手机号 + 注册时间), 我间接 (经由我的直接下级) 推荐了谁 (标记为「二级」「三级」), 不会显示完整链路以外的任何人. 我不能修改我的推荐关系; 我也不能看到我推荐链之外学员的任何信息.

**Why this priority**: 用户没明说要看, 但「我的佣金与下级」是分销闭环里学员唯一能感知价值的入口; 没有它, 学员无法验证管理员承诺的结算是否真实发生.

**Independent Test**: 让 A 推荐 B、B 推荐 C、C 推荐 D. 用 A 登录 → 在分销页看到直接下级 = B (脱敏手机号), 二级 = C, 三级 = D; 看不到 E 之类. 让 C 推荐 D 之外的另一个人 E 时 → A 看到 E 在 A 的「三级」里. 让 F 与 G 完全无关 → F 登录看不到任何关于 A 链的信息, 反之亦然.

**Acceptance Scenarios**:

1. **Given** 学员 A 已登录, **When** 打开学习端「我的分销」页, **Then** 顶部展示四类汇总数字 (待结算 / 已结算 / 已撤销 / 累计), 以及分享链接列表与每个链接的访问人次 / 已绑定新学员数.
2. **Given** A 的链路为 A → B → C → D, **When** A 在「我的下级」视图查看, **Then** 看到 B 标注为「一级」, C 标注为「二级」, D 标注为「三级」; 任何人手机号一律脱敏 (如 138****1234).
3. **Given** A 的某条佣金记录对应被推荐人 X, **When** A 在记录详情查看, **Then** 看到课程、订单时间、级别、金额与状态 (待结算 / 已结算 / 已撤销); X 的手机号脱敏, 不显示 X 的昵称 / 头像 / 学习记录.
4. **Given** A 想从「我的下级」中找到 D 的手机号明文, **When** 操作, **Then** 系统不提供任何明文查看入口, 接口层亦拒绝明文返回, 即便通过浏览器开发者工具自行拼接口也不返回.
5. **Given** 后台把「是否允许学员查看佣金明细」设为「否」, **When** A 访问「我的分销」, **Then** 整页只显示开关状态与说明, 不显示任何金额与下级信息; 配置变更后已加载页面刷新即生效.

### User Story 5 - 管理员审计、撤销与对账 (Priority: P2)

作为管理员, 我可以在管理端看到分销相关操作的全量审计 (配置变更、佣金结算、佣金撤销、课程分销开关变更)、按学员 / 按课程 / 按订单维度对账 (某学员某课程的累计佣金、某订单触发的全部佣金接收人列表与金额), 并对疑似异常的结算 (例如同一订单存在 4 个接收人) 进行撤销. 撤销必须有原因并写入审计; 撤销不会触碰订单快照本身, 只调整佣金记录与对应学员的可结算金额.

**Why this priority**: 合规与对账必备; 用户没明说, 但「超过三级分销即违法」意味着必须有审计可证.

**Independent Test**: 制造一条结算记录后用管理端对账页按订单号查 → 返回该订单的接收人列表与金额; 篡改一笔结算金额 → 对账页立刻反映篡改, 审计页有变更记录; 撤销一笔结算 → 记录状态变为「已撤销」, 关联学员的累计金额同步扣减.

**Acceptance Scenarios**:

1. **Given** 管理员打开「分销对账」并按订单号查询, **When** 输入一笔已结算订单号, **Then** 看到该订单的所有佣金记录: 接收人 (脱敏)、级别、金额、状态、结算时间.
2. **Given** 管理员在分销对账页发现某订单存在 4 个接收人, **When** 选择「撤销」并填写原因, **Then** 系统拒绝并提示「单笔订单佣金接收人不得超过 3, 这是数据完整性硬约束, 请联系技术排查」; 不允许管理员绕过.
3. **Given** 管理员对单条佣金记录执行撤销, **When** 填写原因并确认, **Then** 该记录状态变为「已撤销」, 关联学员的可结算金额按对应级别扣减, 写入审计 (操作者、时间、原因、关联订单与学员).
4. **Given** 订单本身发生退款, **When** 退款成功, **Then** 该订单触发的全部佣金记录由系统自动撤销, 状态变为「已撤销 (订单退款)」, 审计记录操作者 = 系统, 原因 = 「关联订单退款」; 不需要管理员手工操作.
5. **Given** 管理员在分销审计页按时间筛选, **When** 查看, **Then** 看到所有配置变更、课程开关变更、佣金结算、佣金撤销、人工撤销事件, 每条带操作者 / 原因 / 时间, 不得出现「匿名」或「系统未知操作者」.

### User Story 6 - 关闭分销的回退与既有数据处理 (Priority: P2)

作为管理员, 当我把站点分销从「开」切到「关」时, 已经产生的待结算 / 已结算佣金记录不会被删除, 仍按原有结算周期继续走完; 学员的分享入口在学习端停止展示. 老链接是否记访问痕迹, 以该链接**生成当时**的分销开关为准: 生成时为开则继续记未绑定访问并允许后续新注册绑定; 生成时为关则按普通访问处理. 已存在佣金链路不被新配置改写. 管理端配置 / 对账 / 审计页在关站后仍可访问.

**Why this priority**: 合规与运营连续性要求: 关闭分销不能反悔算账.

**Independent Test**: 开启分销并产生一条待结算; 关掉分销 → 待结算记录仍在且金额不变, 学习端分享入口消失, 老链接带来的新注册仍会绑定当时推荐人.

**Acceptance Scenarios**:

1. **Given** 站点分销为「开」且有已生成待结算佣金, **When** 管理员把开关改为「关」, **Then** 已存在记录保持原样并按原结算周期继续; 学习端不再展示「分享 / 我的分销」入口; 审计写入关停时间与操作者.
2. **Given** 站点分销为「关」, **When** 老学员访问其在「开」时获得的分享链接, **Then** 系统按「链接生成当时的分销配置」处理: 若生成时为「开」, 仍按当时规则记为「未绑定访问」, 并允许后续新注册绑定; 若生成时为「关」, 直接按普通访问处理, 不记任何分销痕迹.
3. **Given** 站点分销为「关」, **When** 管理员再次把开关切回「开」, **Then** 学员可重新生成新的分享链接; 旧链接按其各自生成时刻的规则继续走, 不被重新归类.
4. **Given** 课程分销开关被管理员从「开」改为「关」, **When** 该课之后产生的订单结算, **Then** 不再产生佣金记录; 关闭前的记录保留并按原计划结算.

---

### Edge Cases

- 学员 A 邀请的访客 X 注册后, 在结算订单前被管理员封禁学员身份: A 的佣金记录不因 X 被封禁而被撤销, 但 X 的订单本身进入退款流程后, A 的佣金按退款规则撤销.
- 学员 A 自己购买自己推荐人推荐的课程: A 不得因自己下单而获得佣金 (因为 A 不是「被推荐人」), 系统不为此订单给 A 生成任何记录.
- 同一订单被拆单 / 部分退款: 仅退款部分对应的佣金撤销; 未退款部分的佣金按未退款比例结算, 但单笔封顶以**该笔订单最初实付**为准, 不得跨多次拆分累计突破封顶.
- 推荐人 A 在 B 结算之前自己被封禁学员身份: 该笔订单的佣金仍然产生 (因为被推荐人 B 仍合法注册), 但 A 的可结算金额进入「冻结」, 管理员可手动撤销或保留到解封; 系统不得因 A 被封禁而自动把链路「跳过」A 让上层 B 升级为一级.
- 推荐人 A 在结算时已注销 / 销户 (学员身份被关闭): 佣金记录仍生成, 但状态为「待结算 (推荐人账户不可用)」; 管理员按审计流程处置; 不得自动转给任何人.
- 同一访客先后通过 A 与 B 两个推荐人的链接访问, 但只用**一个**新手机号注册: 推荐人取**最后一次有效访问所属的推荐人** (而非首次), 写入决定写死在注册完成时刻, 后续不变.
- 同一访客在注册前清 cookie / 换浏览器 / 换设备: 须再次打开分享短码链接才会写入新的访问痕迹并种新 cookie; 未再次打开即注册则没有推荐人. 不得在注册时凭空生成 visitor token 去绑定.
- 课程已下架但学员在「已下架」前已结算的订单: 佣金按订单结算时刻的配置结算, 不因课程后续下架而被撤销; 但新订单不再产生佣金.
- 课程被删除 (在已下架且无学习记录 / 无订单的前提下才允许删除): 删除课程后, 该课程相关历史佣金记录保留, 但不允许再产生新佣金.
- 管理员关闭整站分销后再开启, 学员分享链接的脱敏形态保持不变, 避免历史截图与对账时串号.
- 分销配置写入时把级别上限填为 0 或负数: 拒绝保存并提示「合规硬约束」, 不视为关站.
- 分销配置写入时把单笔封顶填为 0: 该课程分销名义开启但永远不发放; 该情况作为「关闭分销」对待, 并在管理员配置页红字提醒.
- 同一学员既是 A 的一级, 又是 B 的二级 (通过不同链路), 在 C (A 的二级) 结算时: A 拿二级佣金, 不因为 A 也在 B 链路里就「升级」或「重复拿」.
- 学员 A 推荐注册的手机号, 在 A 不知情的情况下被另一个学员 C 改绑为 C 的手机号 (若存在改绑功能): 改绑不改变已绑定推荐关系, 历史佣金按绑定时刻的学员记录.
- 学员 A 与被推荐人 B 同用一手机号的不同身份 (不可能, 因为手机号在学员档案唯一): 这种情况在注册校验阶段被拒绝.
- 佣金金额因币种 / 精度产生小数: 站点仅使用人民币, 内部以分为单位, 输出时按站点既有金额格式化规则, 不做四舍五入外的额外精度损失.
- 审计或对账页导出 (csv / excel) 涉及手机号: 一律脱敏, 不允许导出明文; 涉及金额字段: 内部以分存储, 导出时按站点既有金额展示规则 (元, 两位小数).
- 推荐关系生成后, 推荐人变更 (例如管理员手工改字段): 不允许, 推荐人字段一旦写入不可修改, 避免通过改推荐人洗链路; 若确需更正, 走审计流程以「作废原记录 + 新增记录」处理.
- 并发: 两个管理员同时改分销配置: 后写者覆盖前写者, 但审计保留两份记录, 不出现「谁覆盖谁」的歧义.
- 并发: 同一订单退款与佣金结算几乎同时发生: 结算在退款事务确认之后才可提交, 退款先到则结算无记录, 结算先到则退款撤销结算记录; 不得出现「退款完成但佣金仍发放」。

## Requirements *(mandatory)*

### Functional Requirements

#### 推荐关系与绑定

- **FR-001**: 系统必须为每名学员 (含未来注册的新学员) 维护一个可空「推荐人」字段, 一旦写入即不可修改 (除非走审计作废流程). 推荐人若存在, 必须也是学员身份, 且与被推荐人不是同一档案.
- **FR-002**: 推荐关系只允许通过「分享链接 → 新学员用未注册手机号注册验证成功」这一条路径产生; 其他任何方式 (管理员手工指定, 旧学员变更手机号, 学员自助填写邀请码等) 不得写入推荐人字段, 至少在首版不得提供.
- **FR-003**: 系统必须为每名学员在生成时颁发独立的「分享入口」(短随机串 + 课程作用域 / 全站作用域), 仅在生成当时返回明文, 之后所有列表与详情只展示脱敏形态.
- **FR-004**: 系统必须区分「分享入口被访客打开 (未绑定)」「新注册绑定成功」「该入口从未带来新注册」三种状态, 并在学员端展示三者的累计计数.
- **FR-005**: 同一访客标识在同一分享入口下, 只有**第一个**用未注册手机号完成的注册获得该入口所属学员为推荐人; 之后无论再用多少手机号, 后续注册不获得推荐人, 也不增加该入口已绑定计数. 同一访客标识先后打开多个分享入口、但只用一个新手机号注册时, 推荐人取注册完成时刻**最后一次有效访问**所属入口的学员.
- **FR-006**: 已注册学员 (无论登录与否) 经任何分享入口打开课程详情页, 不得修改其「推荐人」字段, 也不得为该分享入口增加任何「已绑定」计数.
- **FR-007**: 推荐关系必须持久化在学员档案上, 不依赖 cookie / 设备 / 浏览器作为唯一来源. 访客清 cookie 后须再次打开分享短码链接, 系统为该次打开写入新的访问痕迹并种新 cookie, 随后注册才能绑定. 注册请求若没有对应的访问痕迹, 不得凭空生成 visitor token 并绑定推荐人.

#### 级别与链路

- **FR-008**: 系统必须为每条佣金记录保存「级别」, 取值集合 = {一级, 二级, 三级}; 任何其他级别值 (含「四级」) 不得写入, 系统拒绝保存并记审计.
- **FR-009**: 系统必须按推荐链路上溯, 仅取距离被推荐人最近的最多 3 名祖先推荐人作为该订单的佣金接收人; 链路再长也不得向上追溯第 4 级或更远.
- **FR-010**: 站点级别上限默认值 = 3, 合法写入集合 = {1, 2, 3}; 任何配置写入 (含超级管理员) 不得把级别上限调至大于 3 或小于 1; 写入值 ≤ 0 或 > 3 时, 系统拒绝保存并提示「合规硬约束」. 不得把 0 或负数解释为关站.
- **FR-011**: 同一订单的佣金接收人总人数不得超过 3; 接收人不得重复 (同一学员不得在同一订单中以两个级别出现); 系统在结算前必须做完整性校验, 不通过则拒绝结算并写入审计.
- **FR-012**: 单笔订单的佣金总额不得超过该订单的佣金基数 (订单实付 × 当前比例) 且不得突破单笔封顶; 总和超出时按级别从远到近 (三级 → 二级 → 一级) 截断, 截断部分记为「已截断」不补发.

#### 管理员配置

- **FR-013**: 分销配置必须支持以下开关与参数, 缺一不可, 且每次保存都写审计:
  - 全局开关 (开 / 关)
  - 全局佣金比例 (0% ~ 100%, 课程可覆盖)
  - 佣金计算基数 (订单实付 / 订单标价 / 当前价格快照)
  - 单笔封顶 (元, 0 表示关闭该课程分销)
  - 单学员每课程累计封顶 (元)
  - 全站单学员累计封顶 (元, 可选)
  - 结算周期 (首版固定: 订单成功且退款期结束; 配置页只读展示)
  - 退款撤销规则 (首版固定: 全部撤销)
  - 佣金发放形态 (首版固定: 仅记账, 不挂钱包)
  - 是否允许学员查看佣金明细 (是 / 否)
  - 级别上限 (默认 3, 合法值 1–3)
  - 课程级覆盖: 单课佣金比例 / 单课开关 / 单课单笔封顶 / 单课累计封顶
- **FR-014**: 站点分销关闭时, 学员端的「分享 / 我的分销」入口全部隐藏; 后台仍保留分销配置页与历史记录, 以便复盘与合规备查.
- **FR-015**: 课程级开关与全局开关必须可独立配置; 课程级开关为「关」时, 该课不产生新佣金; 课程级开关为「开」且全局开关为「关」时, 该课仍按课程级配置结算 (允许单课试点).
- **FR-016**: 配置变更必须按订单快照生效: 已存在订单按结算时刻配置结算, 变更后产生的新订单按新配置结算; 不得回溯改写已有结算.
- **FR-017**: 任何佣金相关写操作必须经过审计, 至少记录: 操作者 / 时间 / 类型 (配置 / 课程开关 / 结算 / 撤销 / 自动撤销) / 关联对象 (订单号 / 学员 id / 课程 id) / 变更前后值 (适用时) / 原因 (撤销 / 手工调整必填).

#### 结算与撤销

- **FR-018**: 首版结算周期固定为「订单成功且退款期结束」, 不得在结算中擅自改为其他周期:
  - 订单支付成功: 按当时配置快照写入佣金记录, 状态 = 待结算 (或待结算-推荐人账户不可用); 金额不再因后续配置变更而改写.
  - 退款窗口结束且该订单未退款: 待结算 → 已结算. 「待结算 (推荐人账户不可用)」保持原状态, 不自动升为已结算.
  - 订单退款成功: 该订单全部佣金记录 → 已撤销, 无论当时是待结算还是已结算.
- **FR-019**: 订单退款时, 系统必须将该订单触发的全部佣金记录撤销 (首版唯一规则 = 全部撤销); 撤销由系统而非管理员触发, 但仍写入审计. 「按比例撤销 / 不撤销」首版不提供.
- **FR-020**: 管理员手工撤销单条佣金记录时必须填写原因 (至少 5 个非空字符), 否则系统拒绝执行; 撤销不可撤销 (即撤销本身不可被再次撤销成「已结算」).
- **FR-021**: 佣金金额内部一律以分为单位存储与计算, 输出按站点既有金额展示规则 (元, 两位小数); 不得在结算时引入浮点误差或四舍五入外的精度损失.
- **FR-022**: 学员被封禁 / 销户不影响其作为被推荐人触发的佣金向上游发放 (除非订单本身退款), 但该推荐人若处于「不可结算」状态 (封禁 / 销户), 佣金记录标记为「待结算 (推荐人账户不可用)」, 由管理员按审计流程处置; 不得自动转给其他人, 也不得让上游升级.

#### 学员端可见与脱敏

- **FR-023**: 学习端必须为学员提供「我的分销」入口 (站点开关为「开」且管理员允许学员查看明细时可见), 至少展示: 分享链接列表 (脱敏) + 每链接访问 / 绑定计数; 佣金总览 (待结算 / 已结算 / 已撤销 / 累计); 佣金记录分页 (时间 / 课程 / 被推荐人脱敏手机号 / 级别 / 金额 / 状态); 我的下级视图 (一级 / 二级 / 三级, 全部手机号脱敏).
- **FR-024**: 学员端任何场景下不得暴露其他学员的手机号明文, 不得暴露推荐链路以外的任何学员信息 (昵称 / 头像 / 学习记录), 不得暴露管理员后台配置 (佣金比例 / 封顶值 / 结算周期) 等管理细节.
- **FR-025**: 管理员后台对账 / 审计页同样不得返回学员手机号明文; 导出 csv / excel 时手机号一律脱敏; 审计本身不得包含明文手机号 (以学员 id 引用).

#### 范围排除 (首版不做)

- **FR-026**: 首版不提供: 推荐人手动指定或变更; 推荐码 / 邀请码字段; 学员自助绑定推荐人; 多级分销 > 3 级的任何配置入口; 跨链路合并升级; 跨账户 / 跨币种结算; 提现到银行卡 / 支付宝 / 微信; 把佣金挂入学员钱包或站内余额; 结算周期「订单成功即可 / 管理员手工结算」; 退款「按比例撤销 / 不撤销」; 学员间转赠佣金; 推荐人排行榜 / 邀请竞赛 / 阶梯奖励; 邮件 / 短信 / 推送通道的佣金到账通知 (用既有站内消息, 首版不发到账通知, 仅在「我的分销」可见); 把分销结算数据纳入管理端首页 / 工作台汇总指标.
- **FR-027**: 首版不把推荐关系引入已有学习地图 / 课程访问权 / 激活码兑换等模块的边界规则; 推荐关系仅在结算佣金时被读取, 不得影响学习地图的可见性、访问权授予或激活码的使用.

### Key Entities

- **分享入口 (Share Entry)**: 学员生成的专属入口, 含短随机串、所属学员、生成时刻、生成时分销开关状态. 同一学员可持有多条并可撤销; 明文仅生成当时返回.
- **访问痕迹 (Visit Trace)**: 访客 / 学员在某分享入口下打开课程详情页时留下的痕迹, 含分享入口 id、访问时刻、是否最终绑定为新学员. 用于统计访问 / 绑定计数.
- **推荐关系 (Referral Bond)**: 学员档案上的「推荐人」字段, 一旦写入不可修改; 唯一来源是「分享入口 + 新手机号首次注册」.
- **分销配置 (Distribution Config)**: 站点级 + 课程级配置的总称. 站点级: 全局开关、比例、基数、封顶、周期、撤销规则、发放形态、可见性、级别上限. 课程级: 开关 / 比例覆盖 / 单课封顶.
- **佣金记录 (Commission Record)**: 一笔订单在某个级别上对某个推荐人的应发 / 已发 / 已撤销记录. 包含订单号、被推荐学员 id、推荐人学员 id、级别、金额 (分)、状态 (待结算 / 已结算 / 已撤销 / 待结算 (推荐人账户不可用))、来源 (系统结算 / 系统退款撤销 / 管理员手工撤销).
- **分销审计 (Distribution Audit)**: 所有分销相关写操作的留痕记录. 包含操作者 / 类型 / 关联对象 / 变更前后值 / 原因 / 时间.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在合规前提下, 单笔订单的佣金接收人最多 3 人; 任何一笔订单触发的佣金记录接收人去重后计数 ≤ 3 的比例为 100%.
- **SC-002**: 链路深度 ≥ 4 时, 第 4 级及更远的推荐人在该订单的接收人列表中出现的比例为 0%; 整站不存在「接收人级别 = 四级或以上」的任何记录.
- **SC-003**: 把「级别上限」配置项尝试写入 4 时, 写入失败率为 100%; 没有任何管理员 (含超级管理员) 能解除级别上限 ≤ 3 的硬约束.
- **SC-004**: 对同一订单的佣金记录, 接收人去重后 = 1 笔订单 = 1 条「结算事务」, 不出现同一学员在同一订单中以两个级别重复出现的记录; 该性质在所有订单上的满足率为 100%.
- **SC-005**: 学员 A 推荐注册访客 X (新手机号), X 后续完成订单结算 → A 的佣金记录在「待结算」中可见, 且 A 的下级视图出现 X (脱敏); 该链路在所有合法场景中正确建立的比例 ≥ 99.5%.
- **SC-006**: 老学员 B 经 A 的分享链接访问 → B 的「推荐人」字段不被覆盖, A 的「待结算佣金」不因 B 的访问而增加; 该性质在所有测试场景中满足率为 100%.
- **SC-007**: 同一笔订单在退款成功后 30 秒内, 该订单触发的全部佣金记录状态变为「已撤销」, 且关联学员的可结算金额按对应级别同步扣减; 同步延迟不超过站点既有后台任务的最长周期.
- **SC-008**: 管理员对账页按订单号查询, 返回的接收人总人数 = 该订单佣金记录接收人去重后的人数, 与底层数据 100% 一致.
- **SC-009**: 学员端任何页面、任何接口、任何导出场景中, 返回的学员手机号明文数量为 0; 审计日志中也不包含学员手机号明文.
- **SC-010**: 站点分销关闭后, 学习端「分享 / 我的分销」入口在前端与接口层均不可见的比例为 100%; 历史佣金记录仍可查询, 不被删除或批量改写.
- **SC-011**: 配置变更不导致历史佣金快照被改写; 在任意时刻对任意历史订单回放结算逻辑, 得到的金额与当时实际结算金额一致的回放准确率 ≥ 99.99%.
- **SC-012**: 可用性观察中, 至少 80% 有分销配置权限的管理员能在无额外培训下, 完成「开关 → 配置参数 → 按订单对账 → 撤销异常记录」四步操作, 且能正确说出「级别上限 = 3」是合规硬约束.

## Assumptions

- 分销在站点层与课程层均可配置, 但站点级开关与课程级开关的组合语义 (见 FR-015) 需要在文档里写清楚: 站点关 + 课开 = 仅该课开; 站点开 + 课关 = 全站开但该课关; 两者都开 = 全站开 + 课程可覆盖比例 / 封顶.
- 「直系注册」按用户描述理解为: 推荐关系沿推荐人字段向上追溯, 链路是注册时的有效绑定. 一个新学员只有一个推荐人 (因为只用一部手机号完成注册), 不会出现「同时有两个推荐人」的情况; 跨链路也只取每条链路上最近的三人.
- 「不超过 3 级分销」按用户描述与合规常识理解为: 任意一笔订单的佣金接收人最多 3 名, 按距离被推荐人由近到远标记一级 / 二级 / 三级. 第 4 级及更远的推荐人不拿任何佣金. 这与「一个推荐人最多发展 3 层下线」是不同但兼容的描述, 本规格以「单笔订单接收人 ≤ 3」为准.
- 佣金比例在级别间的分配: 用户没明说, 默认采用「同一比例按级别递减」的简单规则 (例如 100% / 50% / 25% 或全部按同一比例), 实际取值由配置决定, 但必须满足「单笔订单总佣金 ≤ 单笔封顶」与「各级比例之和不得突破封顶」. 具体比例组合在配置页内提供三档预设, 管理员可逐级填写, 但写完后必须满足单笔封顶约束; 不允许填写后让总佣金突破封顶.
- 「结算周期」用户没明说, 首版固定「订单成功且退款期结束」(避免先返后退款). 退款期长度沿用既有订单退款期规则. 配置页只读展示该值, 不提供「成功即可 / 手工结算」切换.
- 「退款撤销规则」首版固定「全部撤销」; 「按比例撤销 / 不撤销」列入 FR-026.
- 「佣金发放形态」首版固定「仅记账」(在「我的分销」页与对账页可见, 不挂入学员钱包, 不发放到任何外部账户). 管理员选择「站内余额」必须拒绝保存.
- 分销相关数据全部走学员档案的「推荐人」字段 + 独立的「分销配置 / 佣金记录 / 分享入口 / 访问痕迹 / 分销审计」五张表, 不引入新的账户类型, 不修改学员主表的「状态」字段语义.
- 短随机串采用与既有「激活码 / 兑换」相同的安全随机源与字符集, 长度沿用既有约定 (例如 8~12 位字母数字, 排除易混字符), 明文仅在生成当下返回, 之后数据库存储可逆加密形态, 显示用脱敏形态 (前 4 后 4 + \*).
- 学习端入口沿用 Element Plus + 现有路由, 新增「我的分销」路由. 管理端权限点写入 PermissionSeeder 共 3 个: `distribution.config` / `distribution.reconcile` (含撤销) / `distribution.audit`. 学员分享与查看走 JWT 学员身份, 不进 seeder.
- 访客在分享链接落地页的体验与普通课程详情页一致; 不引入「邀请人横幅 / 弹窗」之类的强提示, 因为这会泄露推荐人存在; 「由某学员推荐」的存在仅以后台记录形式存在.
- 已有订单快照与既有支付集成 (ZPay) 不变, 分销仅在订单「已结算且未退款」这一外部事件之后才介入; 退款事件也由既有订单事件触发, 分销订阅同一事件源.
- 与 `015` 课程发布核验清单的关系: 课程「关闭分销」与课程「下架 / 草稿 / 已发布」是正交的两条状态维度; 发布核验清单不需要新增分销栏目, 但管理员对账页要能按课程状态筛选佣金.
- 与 `009` 学员优惠券的关系: 佣金计算基数明确选用「订单实付」时, 实付 = 标价 / 优惠价 - 优惠券抵扣, 与既有订单快照口径一致; 不得用「标价」或「优惠价」单独计算后让学员钻空子多拿佣金.
- 与 `010` 课程发布消息的关系: 分佣结算不投递任何系统消息给被推荐人 (因为被推荐人可能根本不知道推荐人存在); 首版不投递佣金到账消息.
- 术语遵循 `CONTEXT.md`: 「学员」「推荐人」「佣金」「分享入口」「访问痕迹」「课程分销开关」「级别」; 避免「下线」「上家」「分销商」「代理」等用词.
- 时区统一 `Asia/Shanghai`; 库内日期时间为 DATETIME, API 与 Zod 输出 ISO-8601 字符串; 不对前端暴露 Unix 秒.
- 学员手机号脱敏形态与站点示例一致: `138****1234`, 正则 `^1[3-9]\d\*{4}\d{4}$`.
- 佣金按每笔成功订单计算, 不是「每课首单」.
- 范围排除清单见 FR-026 / FR-027; 任何首版排除项若被产品要求补齐, 需另起新规格而不是在本规格内增量, 以免把分销的核心合规边界再次模糊化.
