# 功能规格：管理后台标签页与导航增强

**功能分支**：`未创建（项目未配置 before_specify 分支钩子）`

**创建日期**：2026-08-29

**状态**：草稿

**输入**：用户描述："为管理后台添加标签页管理，添加 breadcrumb，为标签页添加默认显示的工作台页面，且支持关闭当前页以及关闭其他、关闭所有的标签页；为全局页面跳转添加 nprogress 进度条。"

## 用户场景与测试（必填）

### 用户故事 1：通过标签页在多个后台页面间切换（优先级：P1）

管理员登录后台后，主内容区上方出现标签页栏。系统默认展示且始终保持一个「工作台」标签。管理员通过侧边菜单或页面内链接打开其他功能页时，系统自动为每个尚未打开的页面新增标签；再次进入已打开页面时，激活已有标签而不重复创建。管理员点击标签即可在已打开的页面之间切换，当前标签与页面内容保持同步。

**优先级原因**：多标签切换是后台高频操作，直接决定管理员在多个业务模块间并行处理任务的效率。

**独立测试**：登录后台后依次从菜单打开「课程管理」「订单管理」，验证默认工作台标签存在、新标签正确出现、点击标签可切换且地址栏与内容一致；再次点击「课程管理」菜单时不新增重复标签。

**验收场景**：

1. **前提** 管理员已登录并进入后台主布局，**当** 首次加载完成，**则** 标签栏显示且包含固定的「工作台」标签，且该标签为当前激活状态。
2. **前提** 标签栏中尚无「课程管理」，**当** 管理员从侧边菜单进入课程列表，**则** 新增「课程管理」标签并激活，页面显示课程列表内容。
3. **前提** 「课程管理」标签已存在且当前激活的是「订单管理」，**当** 管理员再次从菜单进入课程列表，**则** 不新增重复标签，而是激活已有的「课程管理」标签。
4. **前提** 多个标签已打开，**当** 管理员点击某一非当前标签，**则** 该标签变为激活状态，主内容区与地址栏同步切换到对应页面。

### 用户故事 2：通过面包屑理解当前位置（优先级：P1）

管理员在任意后台业务页面时，标签栏下方（或与之相邻的导航区域）显示面包屑。面包屑从后台首页层级逐级展示到当前页面，每一级使用与菜单或页面标题一致的可读名称。管理员可点击面包屑中的上级节点快速返回对应列表或模块入口（若该节点对应可访问页面）。

**优先级原因**：面包屑帮助管理员在深层页面（如课程编辑、学员详情）中快速确认上下文并返回上级，降低迷路成本。

**独立测试**：从「组织管理 → 员工管理」进入后，面包屑显示完整层级；从「课程管理」进入「新建课程」后，面包屑包含课程相关上级与当前页标题。

**验收场景**：

1. **前提** 管理员位于「工作台」，**当** 查看面包屑，**则** 至少显示当前页名称「工作台」，且不出现空白或未知标题。
2. **前提** 管理员位于带上级模块的页面（如组织管理下的员工管理），**当** 查看面包屑，**则** 按「上级模块 → 当前页面」顺序展示可读标题。
3. **前提** 管理员位于详情或编辑页（如新建课程、编辑课程），**当** 查看面包屑，**则** 包含所属模块与当前操作页标题，且与标签页标题语义一致。
4. **前提** 面包屑中存在可点击的上级节点，**当** 管理员点击该节点，**则** 导航到对应页面并更新标签与面包屑状态。

### 用户故事 3：批量关闭标签页（优先级：P2）

管理员可通过标签页上的关闭操作或上下文菜单管理已打开页面：关闭当前标签、关闭除当前外的其他标签、关闭全部可关闭标签。「工作台」作为默认首页标签始终保留且不可关闭。关闭当前标签后，系统自动激活相邻标签；若无其他业务标签，则回到「工作台」。

**优先级原因**：长时间操作会积累大量标签，批量关闭能力是保持界面整洁、避免误关首页的必要补充。

**独立测试**：打开工作台及至少三个业务标签后，分别执行「关闭当前」「关闭其他」「关闭全部」，验证工作台始终保留、关闭后激活页面合理、不可关闭规则生效。

**验收场景**：

1. **前提** 当前激活「订单管理」且存在多个业务标签，**当** 执行「关闭当前」，**则** 「订单管理」标签被移除，并激活合理的相邻标签或「工作台」。
2. **前提** 当前激活某一业务标签且存在多个业务标签，**当** 执行「关闭其他」，**则** 仅保留「工作台」、当前标签及不可关闭的固定标签（若有），其余业务标签全部移除。
3. **前提** 已打开多个业务标签，**当** 执行「关闭全部」，**则** 除「工作台」外所有业务标签被移除，且「工作台」被激活。
4. **前提** 仅存在「工作台」标签，**当** 尝试关闭「工作台」，**则** 操作不可用或被忽略，「工作台」始终保持打开。

### 用户故事 4：页面跳转时显示加载进度反馈（优先级：P2）

管理员在后台内进行任意页面跳转（菜单点击、标签切换、面包屑点击、页面内链接触发路由变化）时，页面顶部出现轻量级加载进度指示。跳转开始时进度条出现并开始推进，目标页面就绪后进度条完成并消失。同一页面内无路由变化的操作不触发进度条。

**优先级原因**：后台部分页面数据加载耗时，全局进度反馈可减少「是否点击生效」的不确定感，提升操作可感知性。

**独立测试**：在后台任意两个页面间切换，观察顶部进度条出现、推进与消失；在同一页面内仅滚动或筛选（不改变路由）时不出现进度条。

**验收场景**：

1. **前提** 管理员位于后台主布局内，**当** 通过侧边菜单跳转到另一页面，**则** 顶部加载进度在导航开始后可见，并在新页面可交互前结束。
2. **前提** 多个标签已打开，**当** 点击非当前标签切换页面，**则** 同样显示加载进度反馈。
3. **前提** 目标页面加载失败或被权限拦截，**当** 导航结束，**则** 进度条仍正常结束，不卡在加载中状态。
4. **前提** 管理员在未登录页或登录流程页，**当** 进行页面切换，**则** 不显示后台主布局的加载进度条（这些页面不在本功能范围内）。

---

### 边界场景

- 管理员通过浏览器地址栏直接输入深层 URL 时，应打开对应标签（若尚不存在则创建）并正确显示面包屑。
- 管理员无权限访问的目标路由被拦截时，不创建无效标签；面包屑与标签状态与拦截后的落点页面一致。
- 同一业务页的不同实例（如两门不同课程的编辑页）应视为不同标签，标题能区分实例（如包含课程名称或标识）。
- 关闭当前标签时若仅剩「工作台」，激活「工作台」且不出现空白内容区。
- 快速连续点击多个菜单项时，进度条不叠加错乱，最终以最后一次导航结果为准。
- 浏览器前进/后退时，标签激活状态与历史记录保持一致。
- 退出登录或会话失效跳转登录页时，清空已打开的业务标签状态，避免下次登录残留。
- 页面标题缺失时，面包屑与标签使用可识别的回退文案（如「未命名页面」），不出现空白标签。

## 需求（必填）

### 功能需求

- **FR-001**：管理后台主布局必须在主内容区上方提供标签页栏，用于展示当前已打开的页面。
- **FR-002**：标签页栏必须默认包含且始终保持一个「工作台」标签；该标签为系统固定首页，不可被用户关闭。
- **FR-003**：管理员通过菜单、链接或其他站内导航进入新页面时，系统必须为尚未打开的目标页面创建标签；已存在对应标签时仅激活该标签，不得重复创建。
- **FR-004**：标签标题必须与页面可读名称一致，优先使用页面配置的标题信息；动态详情页应能区分不同实例。
- **FR-005**：点击标签必须切换主内容区与地址栏到对应页面，且当前标签视觉状态与路由一致。
- **FR-006**：系统必须提供「关闭当前标签」「关闭其他标签」「关闭全部标签」三种操作入口（可通过标签关闭按钮、右键菜单或等效交互触发）。
- **FR-007**：执行「关闭其他」时，必须保留「工作台」、当前激活标签及所有不可关闭标签，关闭其余业务标签。
- **FR-008**：执行「关闭全部」时，必须关闭所有可关闭的业务标签，仅保留「工作台」并激活之。
- **FR-009**：关闭当前标签后，若仍有其他业务标签，必须激活与关闭前相邻的标签（优先保留用户浏览连续性）；若无其他业务标签，必须激活「工作台」。
- **FR-010**：主布局必须在标签栏附近提供面包屑导航，展示从后台入口到当前页面的层级路径。
- **FR-011**：面包屑各级文案必须与菜单或页面标题保持一致；可导航的上级节点必须支持点击返回。
- **FR-012**：面包屑与标签标题在语义上必须一致，避免同一页面出现相互矛盾的名称。
- **FR-013**：后台主布局内的全局路由跳转必须显示顶部页面加载进度指示；进度在导航开始时出现，在导航完成或失败后结束。
- **FR-014**：登录页、首次改密页及其他不使用主布局的页面不得显示该加载进度指示。
- **FR-015**：无路由变化的页面内操作（如表格筛选、弹窗、表单字段编辑）不得触发全局加载进度指示。
- **FR-016**：退出登录或会话失效跳转登录时，必须清除本次会话中打开的业务标签状态。
- **FR-017**：标签与面包屑必须尊重现有权限模型；无权限页面不得作为可访问标签保留在栏中。
- **FR-018**：本功能仅作用于管理后台，不影响学习端现有导航与加载体验。

### 关键实体

- **标签页（Tab）**：表示管理员一次已打开的后台页面实例；包含可读标题、路由标识、是否可关闭、是否固定（工作台）等属性。
- **面包屑路径（Breadcrumb Trail）**：从后台根层级到当前页面的有序导航节点列表；节点包含显示名称与可选的导航目标。
- **导航会话状态（Navigation Session State）**：当前登录会话内打开的标签集合、激活标签及与浏览器历史协同所需的最小状态；登出后重置。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：管理员在打开 5 个不同后台页面后，可在 3 次点击内通过标签切换至任意已打开页面，且内容与地址栏一致率达到 100%。
- **SC-002**：95% 的测试场景中，从菜单进入新页面后 1 秒内可见正确的标签标题与面包屑路径。
- **SC-003**：执行「关闭其他」「关闭全部」后，「工作台」标签保留率 100%，且无空白内容区或孤立无效标签。
- **SC-004**：在 20 次连续页面跳转中，加载进度指示均在导航完成后 500 毫秒内消失，无卡住不消失的情况。
- **SC-005**：可用性测试中，至少 80% 的管理员能在首次使用时无误完成「打开多页 → 切换 → 关闭其他」流程，无需额外说明。
- **SC-006**：直接访问深层 URL、浏览器前进/后退、权限拦截三类边界场景中，标签与面包屑状态正确率 100%。

## 假设

- 「工作台」即管理后台现有默认首页，作为唯一固定标签，首版不增加用户自定义固定页能力。
- 标签状态仅在当前浏览器会话内有效，刷新页面后可不保留已打开标签（若实现会话内内存态）；不要求跨设备或跨浏览器同步。
- 每个可区分的路由实例对应一个标签；同一路由重复进入时复用已有标签。
- 面包屑层级来源于现有菜单结构与页面标题配置，首版不引入独立于菜单的自定义面包屑配置后台。
- 全局加载进度为纯前端导航反馈，不表示后端任务完成；长时间运行的后台任务仍由页面内 loading 状态负责。
- 登录页、首次改密页继续不使用主布局，不在本功能范围内改造。
- 学习端已有或后续的加载反馈实现保持独立，本规格不要求两端行为完全一致。
