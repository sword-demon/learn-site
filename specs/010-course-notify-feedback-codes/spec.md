# 功能规格: 课程发布通知, 意见反馈与激活码兑换

**功能分支**: `010-course-notify-feedback-codes`

**创建日期**: 2026-09-02

**状态**: 草稿

**输入**: 用户描述: "功能一:实现课程发布后智能推送给学员,放在消息通知里面,消息通知里面可以点击到对应的课程详情页,继续使用 webman 的 push 进行实现,需要支持高性能;功能二:为每个课程增加课程意见反馈提交,内容支持富文本; 功能三:为每个课程增加激活码功能,可以通过后台生成对应的激活码,前台学员进行兑换后,也能免于进行购买支付才能看到课程,增加了一个课程的获取的渠道."

**前置规格**: `001-personal-learning-site` (课程发布, 课程访问权, 评价), `003-admin-notifications` (学员消息中心, 已读/未读, 实时提示), `008-api-scale-100k` (大规模投递不得阻塞发布操作)

## 用户场景与测试 (必填)

### 用户故事 1: 课程发布后自动通知学员并可跳转详情 (优先级: P1)

管理员将一门课程从草稿或已下架变为已发布后, 系统自动向当时所有在册学员投递一条「课程发布」消息, 进入学习端个人消息中心. 消息展示课程名称与简短说明, 并提供可点击入口; 学员点击后进入对应课程详情页. 在线学员应在较短时间内看到未读提示, 无需整页手动刷新. 发布操作本身不得因等待全体投递完成而长时间卡住管理员.

**优先级原因**: 新课上架后若只靠学员自己逛分类, 触达慢; 自动写入消息中心并支持一点直达详情, 是本期「智能推送」的最短价值闭环. 高性能是该闭环能在学员规模增长后仍可用的前提.

**独立测试**: 预置若干在册学员 (含一名在线, 一名离线). 管理员发布一门新课; 在线学员在消息入口看到未读增加并可点进该课详情; 离线学员稍后打开消息中心仍能看到同一条未读消息并跳转; 管理员发布确认在投递完成前即可返回.

**验收场景**:

1. **前提** 课程处于草稿且资料完整允许发布, **当** 管理员确认发布, **则** 课程对符合访问条件的访客/学员可见, 同时系统为当时全体在册学员各生成一条未读的课程发布消息.
2. **前提** 课程处于已下架, **当** 管理员再次发布, **则** 再次向当时在册学员投递一条新的课程发布消息 (与历史消息并存, 不覆盖旧条目).
3. **前提** 管理员只编辑已发布课程的简介或目录、不改变发布状态, **当** 保存, **则** 不产生新的课程发布消息.
4. **前提** 学员已登录且保持学习端打开, **当** 其收件箱出现该课程发布消息, **则** 在较短时间内看到未读计数或列表更新, 无需整页手动刷新.
5. **前提** 学员打开该消息或点击其课程入口, **当** 课程仍为已发布, **则** 进入对应课程详情页, 且该条消息变为已读.
6. **前提** 学员打开该消息时课程已下架或不再对学员可见, **当** 点击入口, **则** 看到明确的「课程不可用或已下架」说明, 不得展示受限课节正文, 也不得出现无法理解的空白失败.
7. **前提** 学员未登录, **当** 尝试打开消息入口, **则** 被引导至学员登录, 与既有消息中心行为一致.
8. **前提** 发布时在册学员规模较大, **当** 管理员确认发布, **则** 发布成功确认在数秒内返回, 不等待全体学员收件箱写完; 投递在后台继续, 学员侧最终都能看到消息.

### 用户故事 2: 管理员为课程生成激活码 (优先级: P1)

具备相应权限的管理员在管理端针对一门已发布的收费课程, 按数量批量生成激活码. 每枚激活码只绑定这一门课程, 只能被成功兑换一次. 管理员可查看该课激活码列表 (未使用 / 已兑换 / 已作废 / 已过期), 可为一批码设置可选过期时间, 并可作废尚未兑换的码. 生成与作废须记入审计.

**优先级原因**: 没有可发放的激活码, 学员侧兑换与「免支付获得课程」渠道都不存在.

**独立测试**: 管理员为一门收费已发布课程生成 10 枚带过期时间的激活码, 再作废其中 2 枚未使用码; 列表状态, 数量统计与审计记录一致, 已作废码无法再被兑换.

**验收场景**:

1. **前提** 管理员对某门已发布收费课程具备课程管理权限, **当** 输入生成数量 (在允许范围内) 并确认, **则** 生成相应数量、彼此不同、且只绑定该课程的激活码, 初始状态为未使用.
2. **前提** 管理员在生成时填写过期时间, **当** 生成成功, **则** 该批激活码在过期后不可兑换, 列表标记为已过期.
3. **前提** 管理员未填写过期时间, **当** 生成成功, **则** 激活码在被兑换或被作废前一直可用.
4. **前提** 课程为免费, 或尚未发布 (草稿 / 已下架), **当** 管理员尝试生成激活码, **则** 操作被拒绝并说明仅已发布收费课程可生成.
5. **前提** 存在未使用的激活码, **当** 管理员作废其中若干枚, **则** 这些码立即不可兑换; 已兑换的码不得被作废, 也不改变对应学员的课程访问权.
6. **前提** 管理员打开某课激活码列表, **当** 按状态筛选与分页, **则** 看到码的脱敏展示, 状态, 过期时间, 兑换学员 (若已兑换, 公开身份脱敏) 与兑换时间; 不得一次把全部明文码无保护地对外暴露给无权限者.
7. **前提** 管理员无该课程数据范围或无激活码管理权限, **当** 尝试生成, 查看或作废, **则** 操作被拒绝且不泄露激活码明文.

### 用户故事 3: 学员兑换激活码获得课程访问权 (优先级: P1)

已登录学员在学习端提交一枚有效激活码后, 立即获得该码所绑定课程的课程访问权, 无需创建购买订单, 也无需支付. 兑换成功后, 该课出现在「我的学习」, 学员可打开非试看课节; 课程学员名单中该学员的获得方式为「激活码兑换」. 同一学员对同一课程不得重复有效授权.

**优先级原因**: 这是用户要求的新课程获取渠道, 直接补齐「不走支付也能看课」的商业闭环.

**独立测试**: 预置一门学员尚未拥有的收费课及一枚未使用激活码; 学员兑换后可学习该课完整课节, 订单列表不出现对应购买订单; 同一枚码再次兑换被拒绝; 另一名已通过购买拥有该课的学员提交另一枚有效码时, 码不被消耗.

**验收场景**:

1. **前提** 学员已登录且对该收费课无有效课程访问权, 手中有一枚未使用, 未过期, 未作废的激活码, **当** 提交兑换, **则** 立即获得该课课程访问权, 激活码变为已兑换并与该学员唯一绑定.
2. **前提** 学员已通过兑换获得访问权, **当** 打开该课非试看课节, **则** 行为与支付成功后的访问权相同, 可阅读或播放完整内容并累计学习进度.
3. **前提** 学员已拥有该课有效课程访问权 (无论来自免费加入, 支付成功或先前兑换), **当** 再提交绑定该课的未使用激活码, **则** 兑换被拒绝, 该码保持未使用, 不产生第二条有效授权.
4. **前提** 激活码已兑换, 已作废, 已过期, 不存在或格式无效, **当** 学员提交, **则** 兑换失败并给出可区分的明确原因, 不授予访问权.
5. **前提** 激活码绑定的课程当前不是已发布, **当** 学员兑换, **则** 被拒绝; 课程重新发布后, 仍未使用且未过期的码可以兑换.
6. **前提** 两名学员几乎同时提交同一枚未使用激活码, **当** 系统处理完成, **则** 仅一名成功获得访问权, 另一名收到「已被兑换」类提示, 不出现两人同时拥有由同一枚码授予的访问权.
7. **前提** 学员未登录, **当** 访问兑换入口, **则** 被引导至学员登录.
8. **前提** 学员兑换成功, **当** 管理员查看该课学员名单, **则** 该学员获得方式为「激活码兑换」, 且不存在因本次兑换产生的成功支付订单.

### 用户故事 4: 学员提交课程意见反馈 (优先级: P2)

已取得某课课程访问权的登录学员, 可在该课学习端详情 (或学习页) 提交意见反馈. 正文必须支持富文本 (标题, 段落, 列表, 链接, 基础强调等), 便于说清问题与建议. 反馈只交给运营查看, 不出现在课程公开评价区, 也不替代现有的星级评价.

**优先级原因**: 公开评价面向潜在学员做口碑; 意见反馈面向运营改进内容与体验. 二者混用会污染课程页, 也无法让学员放心写较长的富文本意见.

**独立测试**: 有访问权的学员提交一条含段落与列表的反馈; 课程公开评价区不出现该内容; 无访问权学员无法提交; 管理员随后能在该课反馈列表中看到原文.

**验收场景**:

1. **前提** 学员持有该已发布课程的有效课程访问权, **当** 填写非空富文本正文并提交, **则** 反馈创建成功, 学员看到提交成功确认.
2. **前提** 同一学员对同一课程已提交过反馈, **当** 再次提交另一条, **则** 允许 (不强制「每课仅一条」), 历史条目保留.
3. **前提** 学员没有该课课程访问权, 或未登录, **当** 尝试提交, **则** 被拒绝或引导登录, 不得写入反馈.
4. **前提** 课程页同时存在公开评价入口与意见反馈入口, **当** 访客或学员查看公开评价, **则** 看不到任何意见反馈正文.
5. **前提** 正文为空, 仅含空白, 或超出长度上限, **当** 提交, **则** 在提交前被拒绝并提示原因.
6. **前提** 学员提交的富文本含潜在危险内容 (如可执行脚本), **当** 管理员查看或学员自己回看提交结果, **则** 只按安全后的富文本展示, 不得执行其中的脚本.

### 用户故事 5: 管理员查看与处理意见反馈 (优先级: P2)

具备权限的管理员在管理端按课程查看意见反馈列表, 阅读富文本正文, 看到提交学员的公开身份 (脱敏规则与课程学员名单一致), 提交时间与处理状态. 管理员可将反馈标记为待处理或已处理, 以便跟踪是否跟进. 首版不要求在反馈条目内直接回复学员; 若需回复, 使用既有站内信.

**优先级原因**: 没有后台处理面, 学员提交的反馈无法进入运营工作流.

**独立测试**: 预置同一课程下 3 条待处理反馈; 管理员筛选, 打开详情, 将其中 1 条标为已处理; 列表状态与审计一致, 学员侧公开评价仍不受影响.

**验收场景**:

1. **前提** 某课已有多条反馈, **当** 管理员打开该课意见反馈列表, **则** 默认按提交时间倒序分页, 展示摘要, 提交者公开身份, 时间与处理状态.
2. **前提** 管理员打开一条反馈详情, **当** 查看, **则** 看到完整安全渲染后的富文本正文, 关联课程与提交时间.
3. **前提** 反馈为待处理, **当** 管理员标记为已处理, **则** 状态立即更新, 刷新后保持, 并写入审计.
4. **前提** 管理员按处理状态筛选, **当** 只看待处理, **则** 已处理条目不出现在当前列表.
5. **前提** 管理员无该课程数据范围或无反馈查看权限, **当** 访问列表或详情, **则** 被拒绝且不泄露正文.

### 用户故事 6: 学员从消息中心与兑换入口完成日常操作 (优先级: P3)

学习端在既有「消息」页中展示课程发布消息, 类型标签可区分于公告, 站内信及其他系统消息. 学习端提供明确的激活码兑换入口 (学员中心, 以及学员尚未拥有访问权时的收费课程详情页). 课程发布消息计入未读数量, 标记已读规则与既有消息中心一致.

**优先级原因**: 入口与类型展示决定学员能否发现新能力; 不阻塞 P1 的投递与兑换本身, 但影响日常可用性.

**独立测试**: 学员消息列表中同时有公告, 站内信与课程发布消息, 类型可区分; 从未拥有访问权的收费课详情页能进入兑换; 兑换入口在未登录时引导登录.

**验收场景**:

1. **前提** 学员收件箱含课程发布消息与其他类型消息, **当** 打开消息列表, **则** 课程发布消息有可识别的类型标签, 未读样式与既有消息一致.
2. **前提** 学员对某收费课尚无访问权, **当** 打开该课详情, **则** 在购买区域旁能看到激活码兑换入口, 提交有效码后无需再支付即可学习.
3. **前提** 学员打开学员中心的兑换入口, **当** 输入有效码, **则** 兑换结果与在课程详情页兑换相同.
4. **前提** 学员标记课程发布消息已读, **当** 再次查看, **则** 未读计数正确减少, 重复标记幂等.

### 边界场景

- 发布瞬间没有在册学员: 课程仍发布成功, 不创建学员收件箱条目; 之后新注册的学员不追溯历史发布消息.
- 同一课程在短时间内由草稿 → 已发布 → 已下架 → 已发布: 每次进入已发布都产生一轮新消息, 不合并为一条.
- 学员在全体投递尚未写到自己收件箱时打开消息页: 列表以已经写入的消息为准, 稍后刷新或实时提示到达后出现该条, 不得展示半条或错误堆栈.
- 实时提示暂时不可用: 打开消息页仍能拉到完整课程发布消息; 实时提示是增强, 不是唯一来源.
- 激活码明文足够长且不可被枚举撞库; 连续错误兑换须有可感知限制 (如短暂拒绝), 避免用穷举消耗有效码.
- 激活码列表对管理员展示时, 默认脱敏 (可一次性复制新生成的一批明文, 之后回看为脱敏); 无权限者无法导出.
- 课程从收费改为免费后: 未使用激活码仍可兑换 (兑换后授予访问权, 效果等同已拥有); 新生成仍只允许收费已发布课程.
- 课程访问权来源为激活码兑换时, 不得按「免费加入」那样由管理员一键取消; 行为与支付成功产生的访问权一致 (不可取消).
- 已兑换激活码关联的学员账户被停用: 码保持已兑换, 不可再给他人; 停用学员不能继续学习, 规则与既有停用策略一致.
- 意见反馈与公开评价互相独立: 隐藏评价不影响反馈; 处理反馈不改变评分摘要.
- 课程下架后: 已有访问权的学员仍按既有规则处理学习; 新的意见反馈提交是否开放与该课是否仍可被有权学员打开对齐 (不可打开则不可新提交); 未使用激活码不可兑换直至再次发布.
- 管理端与学习端令牌隔离; 各自受保护操作只接受对应端有效登录.
- 并发重复提交同一条反馈允许产生多条记录, 但须避免因重复点击制造明显的完全重复垃圾 (可由前端防重复提交 + 服务端合理拒绝空内容来约束, 不在首版做复杂去重).

## 需求 (必填)

### 功能需求

#### 课程发布通知

- **FR-001**: 当课程状态变更为已发布 (含首次发布与从已下架再次发布) 时, 系统必须自动向当时全体在册学员投递一条课程发布消息, 无需管理员再手工发送公告或站内信.
- **FR-002**: 课程保持已发布、仅内容或价格被编辑时, 系统不得因此再投递课程发布消息.
- **FR-003**: 课程发布消息必须进入学习端既有个人消息中心, 具备已读/未读, 计入未读数量, 并遵守既有 2 个自然月收件箱清理策略.
- **FR-004**: 课程发布消息必须展示可理解的标题与摘要 (至少含课程名称), 并提供跳转到该课程详情页的入口; 点击后若课程仍可用则打开对应详情, 若不可用则给出明确说明.
- **FR-005**: 学员打开课程发布消息或点击其课程入口后, 该条必须变为已读; 重复标记已读必须幂等.
- **FR-006**: 在线且已登录的学员, 在自己的那条课程发布消息落库后, 必须能通过既有实时提示通道在较短时间内感知未读变化, 无需整页手动刷新.
- **FR-007**: 实时提示不可用时, 学员仍须能通过打开消息列表获得完整, 准确的课程发布消息; 实时提示不得作为唯一数据来源.
- **FR-008**: 管理员确认发布的操作必须在全体收件箱投递完成前即可返回成功; 投递失败或延迟不得把课程状态回滚为未发布, 但必须可追踪 (至少记录投递是否完成及规模摘要), 并允许后续补投且对同一学员同一轮发布不产生重复收件箱条目.
- **FR-009**: 课程发布消息仅目标学员自己可读; 跨学员读取必须拒绝. 停用或删除的学员不在新一轮投递范围内.

#### 激活码

- **FR-010**: 系统必须支持管理员为单门已发布收费课程批量生成激活码; 每枚码只绑定这一门课程, 全局不可与其他码重复.
- **FR-011**: 每枚激活码至多被成功兑换一次; 成功兑换后必须立即失效, 并记录兑换学员与兑换时间.
- **FR-012**: 管理员必须能设置可选过期时间; 过期后未兑换的码不可兑换. 管理员必须能作废未兑换的码; 已兑换的码不可作废, 也不得撤销已授予的课程访问权.
- **FR-013**: 已登录且对该课尚无有效课程访问权的学员, 提交有效激活码后必须立即获得该课课程访问权, 无需支付, 也不得为此创建需支付的购买订单.
- **FR-014**: 激活码兑换是课程访问权的第三种获得方式, 与免费加入, 支付成功并列. 课程学员名单必须能按获得方式筛选并展示「激活码兑换」. 同一学员同一课不得同时存在两条有效授权.
- **FR-015**: 学员已拥有该课有效课程访问权时, 提交绑定该课的未使用激活码必须被拒绝, 且该码保持未使用.
- **FR-016**: 无效, 已兑换, 已作废, 已过期, 或绑定课程当前非已发布的激活码, 兑换必须失败并返回明确原因.
- **FR-017**: 学习端必须提供兑换入口: 学员中心的独立兑换处, 以及学员对该收费课尚无访问权时课程详情上的兑换处. 未登录访问兑换必须引导登录.
- **FR-018**: 由激活码兑换产生的课程访问权不得按免费加入方式取消, 其取消规则与支付成功产生的访问权一致.
- **FR-019**: 管理端必须提供按课程查看激活码列表, 状态筛选, 分页, 生成与作废能力; 关键操作必须写入审计日志. 激活码明文仅在生成成功当下可供管理员复制; 之后列表默认脱敏.
- **FR-020**: 连续失败的兑换尝试必须加以限制, 降低对激活码的穷举风险; 限制触发时学员看到可理解提示, 不得泄露码是否即将有效的额外信息超出必要原因.

#### 课程意见反馈

- **FR-021**: 持有有效课程访问权的登录学员必须能对每门课程提交意见反馈; 正文为必填富文本, 须满足非空与长度上限.
- **FR-022**: 意见反馈必须仅管理员可见, 不得出现在课程公开评价, 评分摘要或树形回复中; 不得替代现有星级评价.
- **FR-023**: 同一学员对同一课程允许提交多条反馈; 每条独立保留提交时间与正文.
- **FR-024**: 无课程访问权者, 访客, 未登录者不得提交该课意见反馈.
- **FR-025**: 管理端必须按课程提供意见反馈列表与详情, 支持按处理状态筛选与分页, 并展示安全渲染后的富文本正文.
- **FR-026**: 管理员必须能将反馈在待处理与已处理之间更新; 状态变更必须写入审计日志.
- **FR-027**: 反馈富文本在任何展示面都必须安全渲染, 不得执行提交内容中的脚本或危险嵌入.
- **FR-028**: 意见反馈与激活码相关接口必须遵循现有权限模型: 管理端受功能权限与课程数据范围约束, 学习端与管理端令牌隔离.

#### 范围排除

- **FR-029**: 首版不提供: 基于兴趣/分类/收藏的个性化收件人筛选, 邮件或短信或操作系统推送, 学员在反馈条目内直接对话回复, 一码多课或一码多次兑换, 激活码转让与转卖, 用激活码抵扣部分金额 (激活码只换整课访问权, 不与优惠券叠加成部分减免), 把意见反馈公开为评价, 以及为免费课程或未发布课程生成激活码.

### 关键实体

- **课程发布消息 (Course Published Notice)**: 课程状态进入已发布时自动生成的系统消息. 投递到每名当时在册学员的收件箱, 关联课程, 可跳转课程详情, 具有已读/未读. 属于既有学员收件箱条目的一种新类型, 不是管理员手工公告.
- **发布投递 (Publish Dispatch)**: 一次课程发布所对应的投递任务摘要, 记录目标规模, 是否完成, 以便核对高性能投递是否结束, 并支持对同一学员同一轮发布的幂等.
- **激活码 (Activation Code)**: 绑定单门课程的一次性兑换凭证. 状态包括未使用, 已兑换, 已作废, 已过期. 成功兑换后授予该课课程访问权.
- **激活码批次 (Activation Code Batch)**: 管理员一次生成操作产生的一组激活码, 共享可选过期时间与生成者, 生成时间.
- **兑换记录 (Redemption)**: 某学员成功使用某枚激活码的记录, 与该码一对一, 并指向因此产生的课程访问权.
- **课程访问权 (Course Entitlement)**: 既有实体. 本期扩展获得方式: 免费加入, 支付成功, **激活码兑换**. 同一学员同一课至多一条有效记录.
- **课程意见反馈 (Course Feedback)**: 学员对某门课程提交的, 仅管理员可见的富文本意见. 含提交者, 课程, 正文, 提交时间, 处理状态 (待处理 / 已处理). 与公开评价不是同一实体.
- **处理状态 (Feedback Status)**: 待处理或已处理, 仅表达运营是否跟进, 不向其他学员公开.

## 成功标准 (必填)

### 可衡量结果

- **SC-001**: 管理员从确认发布到看到「发布成功」, 95% 的场景在 5 秒内完成 (不含等待全体学员都已收到消息).
- **SC-002**: 在 1 万名在册学员规模下, 单次课程发布的收件箱投递在 5 分钟内完成; 投递期间学习端消息列表与标记已读的错误率低于 1%.
- **SC-003**: 在线学员在自己的课程发布消息落库后, 90% 的场景在 5 秒内看到未读提示或列表更新.
- **SC-004**: 学员从消息中心打开仍为已发布的课程详情, 成功到达正确课程页的比例为 100% (在常规网络下, 排除学员主动离开页面).
- **SC-005**: 有效激活码被错误拒绝, 或无效/已兑换/已作废码被错误接受的比例为 0%.
- **SC-006**: 同一枚激活码被并发兑换时, 成功授予访问权的学员数恰好为 1 的比例为 100%.
- **SC-007**: 学员从打开兑换入口到对有效码兑换成功, 90% 的场景在 30 秒内完成 (不含登录耗时).
- **SC-008**: 已拥有课程访问权的学员误兑该课激活码时, 码保持未使用的比例为 100%.
- **SC-009**: 意见反馈正文出现在课程公开评价区的比例为 0%; 有访问权学员提交合法反馈的成功率 ≥ 99%.
- **SC-010**: 可用性测试中, 至少 80% 的学员能在无额外培训下完成「看到发布消息并进入课程」以及「兑换激活码后打开课节」; 至少 80% 的管理员能完成「生成激活码」与「把一条反馈标为已处理」.

## 假设

- 「智能推送」首版指: 课程一旦进入已发布即自动写入全体在册学员的消息中心, 并带课程跳转入口, 在线学员走既有实时提示. 不引入按分类, 收藏, 历史学习记录做收件人筛选, 也不引入推荐模型. 若后续要做兴趣定向, 另开规格.
- 「在册学员」与 `003` 一致: 状态正常, 可登录学习端的学员账户; 停用或已删除账户不在投递范围. 发布后新注册学员不追溯该条历史发布消息.
- 课程发布消息是系统自动通知的新类型, 复用 `003` 的学员消息中心, 已读/未读, 未读计数, 2 个月清理, 以及实时提示通道; 管理员通知模块不必为此新增「手工撰写课程发布」表单.
- 用户明确要求继续使用站点既有的学习端实时推送能力, 并要求高性能. 投递策略对齐 `008`: 发布确认与全体写收件箱解耦, 同一轮发布对同一学员幂等, 实时提示为增强, 列表拉取为兜底. 不新增邮件, 短信或操作系统级推送.
- 激活码是「整课访问权」的新渠道, 不是优惠券, 也不是部分金额抵扣. 与 `009` 优惠券, 课程限时优惠价互不替代.
- 激活码形态为系统生成的高熵字符串, 供复制粘贴, 首版不要求学员口播短口令. 单次生成数量默认上限 1,000 枚, 单次下限 1 枚.
- 过期时间按站点统一时区 `Asia/Shanghai` 解释; 未设置过期表示只在兑换或作废时结束生命周期.
- 激活码兑换授予的课程访问权与支付成功同等对待: 不可按免费加入取消. 管理员作废只作用于未兑换码.
- 课程学员名单既有「获得方式」筛选增加「激活码兑换」; 学习人数统计仍按有效课程访问权人数, 不区分来源.
- 意见反馈入口放在学员已能学习的课程详情或学习页, 不放在公开评价表单内. 首版管理员不在反馈详情里直接回复; 需要触达学员时使用既有站内信.
- 富文本能力对齐站点已用于课程简介的安全子集 (标题, 段落, 列表, 链接, 粗体/斜体等), 不引入与课程简介不一致的新嵌入类型 (如任意 iframe).
- 意见反馈, 激活码列表均受该课程既有数据范围约束; 超级管理员不受限. 功能权限以课程管理相关权限点扩展或新增最小必要权限码, 细粒度「只读反馈 / 只作废码」拆分不在首版.
- 领域用语遵循 `CONTEXT.md`. 实现前须把「激活码」「兑换」「课程意见反馈」「课程发布消息」写入领域词表, 并将「课程访问权」的获得方式从「免费加入或支付成功」扩展为包含「激活码兑换」. 避免把意见反馈叫做评价, 把激活码叫做优惠券或优惠码, 把课程发布消息叫做公告或站内信.
- 首版不改访客未登录即可看的课程目录与试看规则; 无访问权者仍只能看摘要与试看课节, 直到免费加入, 支付成功或兑换激活码之一完成.
