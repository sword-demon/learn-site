## 用户场景与测试（必填）

### 用户故事 1：管理员查看自动任务列表（优先级：P1）

具备自动任务管理权限的管理员在管理后台打开「自动任务」模块，查看系统中已注册的全部自动任务。列表展示任务名称、任务类型说明、当前调度表达式、启用状态、最近一次执行结果摘要、下一次预计执行时间。管理员可快速识别哪些任务正在运行、哪些已暂停、哪些近期执行失败。

**优先级原因**：没有可浏览的任务清单，运维无法掌握站点后台定时工作的整体状态，也无法定位异常任务。

**独立测试**：预置至少 2 条自动任务（含 1 条启用、1 条停用），管理员登录后打开列表，验证字段完整、状态与数据一致。

**验收场景**：

1. **前提** 管理员已登录且具备自动任务管理权限，**当** 打开自动任务列表，**则** 展示全部已注册任务，默认按任务名称或创建时间有序排列。
2. **前提** 某任务处于启用状态且调度表达式有效，**当** 查看列表，**则** 显示该任务下一次预计执行时间。
3. **前提** 某任务最近一次执行失败，**当** 查看列表，**则** 在最近执行摘要中可见失败标识或状态，便于快速发现异常。
4. **前提** 管理员无自动任务管理权限，**当** 尝试访问列表或相关接口，**则** 操作被拒绝且不泄露任务配置或日志内容。

---

### 用户故事 2：管理员通过表单配置自动任务（优先级：P1）

管理员在后台编辑自动任务：设置或修改调度表达式、启用或停用任务，并在保存前校验表达式语法。对于支持参数的任务类型，可通过表单填写约定范围内的配置项（如批处理大小、保留天数等）。保存成功后，任务按新配置在后续调度周期内自动执行；停用后不再触发新的自动执行。

**优先级原因**：表单化配置是本功能的核心价值，使定时工作无需改代码或登录服务器即可调整。

**独立测试**：修改某任务的调度表达式并保存，验证表达式校验、下一次执行时间预览更新；停用任务后等待一个调度周期，确认不再产生新的自动执行记录。

**验收场景**：

1. **前提** 管理员打开某任务编辑表单，**当** 输入合法调度表达式并保存，**则** 配置持久化成功，列表显示更新后的表达式与下一次预计执行时间。
2. **前提** 管理员输入非法或无法解析的调度表达式，**当** 尝试保存，**则** 保存被拒绝，并给出可理解的校验错误提示（说明表达式不符合约定语法）。
3. **前提** 管理员在保存前查看「下一次执行时间」预览，**当** 修改表达式但未保存，**则** 预览随当前表单输入实时或按需更新，帮助确认调度是否符合预期。
4. **前提** 管理员将任务设为停用，**当** 保存成功，**则** 该任务不再按调度自动触发，但历史执行日志仍可查询。
5. **前提** 管理员将已停用任务重新启用，**当** 保存成功，**则** 任务恢复按表达式调度，下一次执行时间重新计算并展示。

---

### 用户故事 3：系统自动执行已启用的任务（优先级：P1）

对于处于启用状态且调度表达式有效的自动任务，系统按表达式在后台自动触发执行，无需人工介入。每次执行产生一条执行记录，记录开始时间、结束时间、执行结果（成功或失败）、失败时的错误摘要。执行过程不得因单条任务失败而导致整个定时调度进程崩溃；并发或重叠调度时行为可预期（见假设）。

**优先级原因**：自动执行是定时任务模块的存在意义；没有可靠执行与结果记录，配置界面没有实际价值。

**独立测试**：配置一条短周期任务（如每分钟），观察在数个周期内是否按时触发、日志是否连续完整；模拟任务逻辑失败，验证失败被记录且调度器仍可继续服务其他任务。

**验收场景**：

1. **前提** 任务已启用且表达式为「每 N 分钟执行一次」，**当** 到达调度时刻，**则** 任务被自动触发一次，并写入一条执行日志。
2. **前提** 任务执行过程中业务逻辑抛出可恢复错误，**当** 执行结束，**则** 执行日志标记为失败并记录错误摘要，调度器仍可继续调度其他任务与后续周期。
3. **前提** 站点 API 服务正常运行，**当** 多个启用任务在同一时刻触发，**则** 各任务均产生独立执行记录，不出现日志丢失或状态混淆。
4. **前提** 任务已停用，**当** 到达原调度时刻，**则** 不产生新的自动执行记录。

---

### 用户故事 4：管理员查询自动任务执行日志（优先级：P1）

管理员在自动任务模块中查看执行日志：可按任务、执行结果（成功/失败）、执行时间范围筛选，并分页浏览。列表展示任务名称、触发方式（自动调度或手动触发）、开始时间、耗时、执行结果。可打开单条日志查看详情，含失败时的错误摘要及必要的上下文信息，用于排障与运营核对。

**优先级原因**：完整的执行日志是运维定位「任务是否跑了、何时跑、为何失败」的唯一依据，与用户对「完整日志」的明确要求一致。

**独立测试**：对同一任务触发多次执行（含至少 1 次失败），在日志列表按任务与结果筛选，验证记录完整、筛选准确、详情可读。

**验收场景**：

1. **前提** 系统中已有若干执行记录，**当** 管理员打开执行日志列表，**则** 默认按开始时间倒序展示，并显示任务名称、触发方式、开始时间、耗时与结果。
2. **前提** 管理员筛选某任务且结果为「失败」，**当** 应用筛选，**则** 仅返回该任务的失败记录。
3. **前提** 管理员设置执行时间范围，**当** 应用筛选，**则** 仅返回该时间范围内的记录。
4. **前提** 管理员打开某条失败日志详情，**当** 查看详情，**则** 可见错误摘要及足以支持初步排障的上下文，且不暴露无关敏感数据。
5. **前提** 记录数量超过单页上限，**当** 翻页，**则** 分页结果连续且不重复、不遗漏。

---

### 用户故事 5：管理员手动触发任务执行（优先级：P2）

具备权限的管理员可对已注册任务执行「立即运行一次」，用于验证配置、补跑或故障恢复后的试运行。手动触发与自动调度产生的执行记录在同一日志体系中区分触发方式，且手动触发不修改任务的调度表达式与启用状态。

**优先级原因**：手动触发显著降低运维验证成本，但不影响首版「查看—配置—自动执行—查日志」主路径的闭环。

**独立测试**：对某任务点击立即执行，验证短时间内产生一条「手动触发」日志；表达式与启用状态保持不变。

**验收场景**：

1. **前提** 管理员在任务列表或详情对某任务执行立即运行，**当** 操作成功，**则** 产生一条标记为手动触发的执行日志，且任务调度配置不变。
2. **前提** 同一任务在短时间内被多次手动触发，**当** 各次执行完成，**则** 每次均产生独立日志条目，结果彼此独立。
3. **前提** 管理员无自动任务管理权限，**当** 尝试手动触发，**则** 操作被拒绝。

---

### 边界场景

- 调度表达式为空、全空白或明显非法时，保存与预览均应拒绝并提示，不得写入无效配置。
- 表达式合法但指向极频繁调度（如每秒）时，系统应给出风险提示或上限约束（见假设），避免无意造成资源耗尽。
- 任务执行时间跨越整点或长耗时任务仍在运行时，下一次调度行为符合约定策略（见假设：不重复堆叠或跳过，需在实现阶段固定一种策略并写入运维说明）。
- 服务重启或部署后，已启用的任务应在调度进程就绪后按表达式继续工作，不丢失配置。
- 某任务类型在代码中下线但数据库仍有记录时，列表应标识为不可用或只读，不得通过表单误启导致无法执行的死任务。
- 日志数据量长期增长时，列表查询在常规数据量下仍可在可接受时间内返回（见成功标准）；超大规模历史日志的归档策略不在首版范围。
- 并发编辑同一任务配置时，后提交者应得到明确冲突或覆盖策略结果，不产生 silent 丢失。
- 手动触发与自动调度在同一时刻重叠时，行为可预期（见假设），且均留有日志。
- 无执行记录的任务在列表中显示「尚未执行」或等价空态，不展示错误信息。
- 筛选无结果时显示空态，不展示内部堆栈或系统路径。

## 需求（必填）

### 功能需求

- **FR-001**：管理后台必须提供独立的「自动任务」模块入口，仅对具备自动任务管理权限的管理员可见。
- **FR-002**：系统必须维护一份可管理的自动任务目录；每条任务具有唯一标识、名称、类型说明、调度表达式、启用状态及可选的类型相关参数。
- **FR-003**：自动任务类型由系统预注册（代码侧注册处理器），首版不得允许管理员通过界面执行任意系统命令或注入未审核的业务逻辑；管理员仅可配置已注册类型的调度与约定参数。
- **FR-004**：管理员必须通过表单编辑任务的调度表达式；表达式必须符合项目采用的 cron 风格语法（含秒级字段的六段式表达式，与现有定时组件约定一致），保存前须通过语法校验。
- **FR-005**：在编辑表单中，管理员必须能够在保存前查看基于当前表达式计算的「下一次预计执行时间」；非法表达式时预览应明确提示无法计算。
- **FR-006**：管理员必须能够启用或停用任务；停用后不得产生新的自动调度执行，历史日志仍可查询。
- **FR-007**：对已启用且表达式有效的任务，系统必须按表达式自动触发执行，无需人工操作。
- **FR-008**：每次任务执行（自动或手动）必须写入一条执行日志，至少包含：关联任务、触发方式、开始时间、结束时间或耗时、执行结果（成功/失败）、失败时的错误摘要。
- **FR-009**：管理后台必须提供执行日志列表，支持按任务、执行结果、执行时间范围筛选，以及按开始时间倒序分页查询。
- **FR-010**：管理后台必须提供单条执行日志详情，展示足以支持运维排障的信息；不得向无权限用户暴露日志内容。
- **FR-011**：具备权限的管理员必须能够对任务执行「立即运行一次」；手动触发须在日志中区别于自动调度。
- **FR-012**：任务列表必须展示：名称、类型说明、调度表达式、启用状态、最近一次执行结果摘要、下一次预计执行时间（在可计算时）。
- **FR-013**：首版须将现有「学员消息收件箱过期清理」类定时工作纳入可管理任务体系，使该清理任务可通过本模块查看状态与日志，并可通过表单调整调度表达式与启用状态（业务清理规则本身不在本模块修改）。
- **FR-014**：单条任务执行失败不得导致整个定时调度服务不可用；其他任务与后续调度周期应能继续。
- **FR-015**：自动任务相关接口与页面必须遵循现有权限模型：管理端与学习端令牌隔离，学习端不得调用管理端自动任务接口。
- **FR-016**：关键操作（创建/更新任务配置、手动触发、任务执行完成）须与现有审计能力对齐，至少记录可追踪的操作类型、操作者或系统标识、时间。
- **FR-017**：首版不提供执行日志的批量导出、告警通知（邮件/站内信）、任务依赖编排或多步骤工作流；仅支持单任务调度与日志查询。

### 关键实体

- **自动任务（Scheduled Task）**：系统中可调度的工作单元；包含名称、任务类型（绑定预注册处理器）、调度表达式、启用状态、可选参数、下一次预计执行时间（可计算时缓存或实时计算）、最近一次执行摘要。
- **任务类型（Task Handler Type）**：代码侧注册的可执行任务种类；定义人类可读说明、可配置参数模式及业务执行逻辑；管理员只能选择已注册类型，不能自创类型。
- **调度表达式（Schedule Expression）**：描述任务触发时刻的 cron 风格字符串；须支持语法校验与下一次执行时间预测。
- **执行日志（Task Run Log）**：单次任务运行的记录；包含触发方式（自动/手动）、时间范围、结果状态、错误摘要及关联任务。
- **触发方式（Trigger Type）**：区分调度器按表达式自动触发与管理员手动触发，用于日志筛选与审计。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：管理员从打开任务编辑表单到成功保存合法调度配置，95% 的场景在 1 分钟内完成（含预览下一次执行时间）。
- **SC-002**：非法调度表达式在保存时 100% 被拦截，且管理员能看到明确校验提示，不产生无效配置入库。
- **SC-003**：对已启用且表达式为「每 1 分钟」的测试任务，在连续观察 5 个调度周期内，自动触发次数与周期数一致（允许 ±10 秒时钟偏差），且每次均有对应执行日志。
- **SC-004**：管理员打开执行日志列表，95% 的场景在 2 秒内看到第一屏结果（常规数据量与常规网络）。
- **SC-005**：任务执行业务逻辑失败时，失败日志写入成功率 99% 以上，且同进程内其他启用任务在随后调度周期内仍可正常触发。
- **SC-006**：手动触发操作从提交到产生可查询日志，90% 的场景在 30 秒内完成（不含任务本身长耗时业务）。
- **SC-007**：权限隔离测试：无自动任务管理权限的账号访问列表、配置、日志、手动触发接口时，拒绝率 100%，且不泄露任务配置或日志内容。
- **SC-008**：可用性测试中，至少 80% 的管理员能在无额外培训下完成「查看任务列表 → 修改调度表达式并预览下次执行 → 查看最近一次日志」流程。

## 假设

- 调度表达式采用与现有 API 定时组件一致的六段式 cron 语法（秒、分、时、日、月、周），而非仅五段式 Unix cron；校验与下次执行时间预测均基于该约定。
- 任务类型为代码预注册；首版至少包含「学员收件箱消息过期清理」类型，并与既有清理策略（如超过 2 个月的收件箱记录）对齐；新增类型通过后续版本扩展，不在本模块动态上传脚本。
- 同一任务在单次执行尚未结束时若再次到达调度时刻，首版采用「跳过本次调度、等待当前执行结束后再按表达式继续」或「不并发、记录跳过」中的一种固定策略，并在实现阶段写入运维说明；不在首版提供可配置的并发策略。
- 对极频繁调度设置合理下限（如最短间隔不少于 1 分钟），防止误配置导致资源耗尽；具体下限在实现阶段定义并在表单校验中体现。
- 「下一次预计执行时间」基于服务器当前时区与系统时钟计算；跨时区展示首版与站点现有管理端时区约定一致。
- 执行日志长期保留供运维查询；首版不自动清理日志，仅对日志列表做分页；若单表过大，归档策略留待后续版本。
- 自动任务管理权限以单一权限码（如 `scheduled_task.manage`）控制列表、编辑、手动触发与日志查询；更细粒度（仅读、仅执行）不在首版范围。
- 定时调度运行在 API 服务进程内，与现有容器化部署契约一致；服务重启后从持久化配置恢复调度，无需人工重配。
- 学习端、访客与学员不可见自动任务模块与任何执行日志；本功能纯管理端能力。
- 手动触发与自动调度重叠时，两种触发均各自产生执行日志，不在首版合并为单次运行。
