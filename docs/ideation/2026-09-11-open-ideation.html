Grounding Context

个人运营的单站点虚拟课: 学习端 SPA、管理端 SPA、Webman API. 学员用大陆手机号, 后台用户用后台账号, 永不合并. 商业闭环已经齐: 免费加入 / 支付成功 / 激活码兑换三种课程访问权, 付费与兑换不可撤销, 免费加入才可取消. 学习地图只推荐路径, 不发课权. 课节问答对已授权学员公开. 触达只有站内消息和可选浏览器 Push. 分销最多 3 级, 只记账不进钱包. 漏斗只报事实, 禁止伪因果.

已上线且不要再发明一遍的: 激活码、优惠券领取、ZPay、下一步行动、内容待办、3 级分销账本、发布核验. 本地 WIP 是 017-learning-fact-funnel, 尚未合入. 没有 STRATEGY.md. 增长口令从宪章和 001 读出来: 让已购学员把课学完, 让站长看见力气值不值. 不是多机构商城、不是讲师入驻、不是原生 App.

外部 2026 年独立课站在扩会员、教练门户、社群 OS、课内 AI 助教、训练营和学考练. 对本仓库, 那些大多是换公司. 空相邻格里能留下来的, 是买断之上的持续田、公开问答沉淀成教材、路径上的逐课结账、以及一人运营可缺席的站内节拍.

1.

买断田亩操作系统

把「一次买断过时」翻过来: 已购课是学员名下一块只增不收的田, 不是 SKU 残骸. 登录后的默认页不再是分类树, 而是一条可解释的下一步 (未完成订单、可领的券、未学完的课、未读的持证勘误). 分类树降到 /courses, 首页上的「推荐学习地图」轨道拆掉, 因为它已经在用推荐位说话. 课程再版或课节勘误只投给此刻仍持有该课访问权的人, 文案只报事实, 不写「因为你喜欢」. 不做会员档, 不做可打印证书.

Description
登录默认路由从分类树改成继续场; 发布/勘误的默认听众从全体在册改成相关访问权; 产品叙事从拉新改成养田. 可打印「学完证书」不在这个方向里.
Basis
direct: CONTEXT 把首页钉成分类树且避免推荐位; HomeView.vue 却同时放了 next-action、分类树和推荐地图轨. LearningActionService 已按 orders → coupons → learning_progress → notifications → learning_maps → favorites 算出一条可解释动作. CONTEXT 课程发布消息默认全体在册; 015 FR-034 禁止的是兴趣/分类筛选, 不是按访问权过滤. ADR-0002: 支付成功的访问权一律不可取消, 下架后付费学员默认仍能学.
Rationale
已购学员打开站点仍先看到逛店, 等于每天把「把课学完」让给「再买一门」. 买断制要有持续田, 才对得起不可撤销的课权, 而不必改成会员公司.
Downsides
改登录默认路由会动 CONTEXT / 001 的首页定义, 需要一次词表修订. 按访问权投递会让未购学员更少看到上新, 拉新要另找入口. 实现上要分清「该课持权」和「同地图邻步」——后者已经靠近推荐, 首版应只做持证人.

2.

公开答疑产线

课节问答已经选择公开, 是为了少回答第三次. 现在缺的是闸门和出口. 提问前先碰撞同课节已回答的公开问答, 声明「这些都不能回答我」才创建新问题. 内容待办关闭后, 把问+答钉回该课节顶部做成勘误牌, 原问题标成已吸收. 若上 AI, 只允许它写 content_todo_candidates 的新版本, 人工批准才进课节. 不做课节聊天机器人, 不做私密辅导, 评价不进这条流水线.

Description
提交闸门 + 关闭后写回课节 + AI 锁在候选稿. 漏斗「过阈自动开待办」不在这个方向里, 017 禁止把未转化叫做流失.
Basis
direct: ADR-0006: 答疑价值在于减少重复提问, 并把问题留在课节上下文; 一对一私密答疑不走本产品. 001 FR-042/FR-045 有权学员从课节提问且问答公开. 内容待办已能写回课节并维护候选版本. external: 工厂 Andon / 病区白板: 可见性本身就是产能. 小鹅通式课内助教对本产品应收缩成候选稿, 而不是会话产品.
Rationale
一人答疑的时间不线性可扩, 改一课却是永久资产. 这是外部「课内 AI」空位接到已有 content-todo 的唯一不换公司的接法.
Downsides
碰撞做不好会误伤真新问题. 写回课节会改变已购学员正在看的正文, 需要持证人勘误通知 (见想法 1) 才能不吓人. AI 候选稿仍要人审, 省不掉判断, 只省打字.

3.

路径店不是套餐

学习地图永远不发课权. 每个节点分成两种动词: 「去办这一段的许可」(免费加入 / 结算 / 激活码) 和 「继续已许可路段」. 若要提高客单, 另售「一笔订单、多门课」: 逐门签发与单课支付相同的不可取消访问权, 成交后可选写入一张地图学习记录. 地图不是 SKU, 增课不追溯赠送, 减课不回收已授权利. 明确拒绝「买地图送全部课」.

Description
地图交互先把「许可 / 继续」说清楚; 商业上新增多课访问权订单, 而不是地图通用券或会员桶.
Basis
direct: ADR-0004: 学习地图是推荐路径, 不是套餐或训练营售卖; 开始地图不得自动获得其中每门课的访问权; 同一课可出现在不同地图, 进度与访问权始终是两份记录. CONTEXT 避免「训练营, 专栏, 套餐」. 009 FR-015 首版不做地图/套餐通用券. 001 把套餐售卖列在范围外, 所以这是新规格, 不是 001 增量. external: Kajabi Backstage 把已有目录重绑成高客单服务, 结构可借, 门户私密性不可借.
Rationale
个人站点要卖「一条路」时, 这是唯一不拆毁买断规则的高客单缝. 地图已经有进度和下一步, 缺的是商业包装, 不是再做推荐首页.
Downsides
一单多课会逼问优惠券怎么摊、分销佣金按哪门课快照、发票要不要拆行. 地图 CTA 若只是把已有「无访问权」写得更响, 单独开会不够格, 必须和订单对象绑在一起才值得做. 与 001 范围外的套餐禁令需要一次明确的词表: 我们卖的是访问权集合, 不是套餐商品.

4.

锁门外的双轨身份恢复

帮助页把登录异常推到「联系客服」, 规格又禁止邮箱和短信自助找回, 于是每一次忘密都是微信侦探. 主路径: 仍持有效登录态的设备, 用现会话设新密码. 全掉线: 学员用手机号 + 最近订单后四位或激活码后四位自证, 写入运营收件箱, 管理员核验后走已有密码重置并 writeAudit(). 帮助不再写联系客服, 改指向这条事故台. 不引入邮箱登录, 不把短信当主触达.

Description
两级恢复, 都长在已有手机号、订单、激活码和管理员重置权限上. 日常改密不再占用站长下午.
Basis
direct: apps/web/src/content/help.ts: 「如遇登录异常…或联系客服协助处理」. 001 FR-003: 找回凭据由管理员重置, 不提供邮箱或短信自助找回. ADR-0001 禁止邮箱登录. CONTEXT 把学员自助找回避开首版. 管理端已有重置权限与踢下线. 付费访问权不可取消, 所以人锁在门外等于课也丢了.
Rationale
这是买断交付裂缝里最致命、也最小的一刀: 不改身份模型, 只把口头处理收成可审计手续.
Downsides
订单后四位不是强核身, 要防枚举和冷却. 运营收件箱今天是异常队列, 学员工单要小心不要和内容待办搅在一起. 登录态改密要处理多设备 refresh.

5.

一人出版社安全网

发布核验已经能挡住硬错误, 但开同类第二门课仍从空表单重填, 误发一节视频也没有不伤害进度的撤回. 媒体还直接落 status='ready', 删课不回收磁盘. 三件套: 新建课程改为 fork 上次通过的发布清单快照 (骨架与规则, 不含学员/订单/问答); 误发只回滚目录可见性, 不回退进度、订单、付费访问权; 未处理完的资源不得标 ready, 删除进入 GC. 不是历史版本浏览器, 不是讲师货架.

Description
目录劳动、误发、假播放器三处一人运营不敢点发布的根, 一次收成安全网.
Basis
direct: HANDOFF: 课程复制/模板不实现; Asset GC 删课不删盘; Asset 直接 status='ready'. 015 FR-034 不做可对照历史版本浏览与回滚到任意历史目录; FR-026 生成清单不得把已完成进度回退. ADR-0002 管理员不能取消支付成功产生的访问权.
Rationale
一人站点的增长往往是同一教法的下一门课. 没有后悔药, 内容迭代会停, 买断田也会荒.
Downsides
可见性回滚仍可能让正在看的学员迷路, 需要持证人通知. fork 会复制过期价格或试看标记, 清单必须再跑一遍. GC/转码是基础设施, 若单独做会滑成平台工程; 必须绑在「已购播放诚实」上才算产品方向.

6.

场外银行与铸造宪法

分销已经有不可变推荐人和佣金快照, 但规格不做钱包、提现、到账通知, 却预留「过退款窗口再结算」. 收费闭环没有退款. 正确仪式: 按账期导出最多 3 级应发明细, 管理员标记已场外打款 (金额 / 渠道 / 凭证备注 / 审计), 学员只在「我的分销」看应发 / 已发. 系统永远不当支付机构. 同时把「铸造时快照」从分销特例升级成宪法: 凡生成学员权利或商业承诺的行, 插入时钉死当时的站点开关, 运行时只读快照, 关掉全局开关不得追溯杀死活承诺.

Description
结算是事实导出, 不是资金托管. 优惠券、Banner、激活码、白名单若要可关停, 必须先有 mint 快照列.
Basis
direct: 016 FR-026 排除提现、钱包、到账通知、工作台分销指标, 以及结算周期「订单成功即可 / 管理员手工结算」和退款撤销变体. ADR-0002: 收费闭环没有退款. ShareEntryService 已 snapshot distribution_enabled_at_creation. 测试教训点名 ActivationCode / Coupon / Banner / PaymentWhitelist 是同类可开关面.
Rationale
只记账则没人持续分享; 做钱包则个人课站变成资金盘. 无退款宪章下, 场外核销是唯一能做完的结算.
Downsides
场外打款仍要站长每周动手, 只是不再靠微信聊天记录当唯一凭证. 016 把「管理员手工结算」也写进了首版不提供, 核销页是新规格, 不是 016 增量. 快照宪法会让「立即关掉某能力」变慢, 这是故意的.

7.

活开关说明书

帮助中心仍是 help.ts 里一份 2026-09-01 的静态 HTML, 改一句要重建学习端镜像, 文案还在教「联系客服」并指向退款说明. 把帮助收成与 site_settings 同命运的说明书: 关了的分销 / 优惠券 / 签到 / 激活码从页面消失; 宪章级句子 (付费即交付、地图不发权、无邮件主通道) 钉在结算、激活码、地图、签到这些动词发生处. 不是 Zendesk, 不是可检索帮助站.

Description
一份由开关快照生成的短安全卡, 加上现场铭牌. 事故台入口 (想法 4) 写在登录页, 不写在客服神话里.
Basis
direct: apps/web/src/content/help.ts 的 updatedAt: '2026年9月1日', 登录异常导向客服, 并含「退款规则请参阅《退款说明》」. 这与 ADR-0002 收费闭环没有退款直接打架. 功能开关已在分销等处 snapshot-at-mint. 内容待办计划也写过不把帮助中心当可编辑产品, 所以本方向是开关生成, 不是 CMS.
Rationale
静态帮助正在用另一套宪章说话. 口径变更成本若等于一次前端发版, 运营就不会改口径, 只会私聊解释.
Downsides
开关生成的文案容易生硬. 现场铭牌要控制数量, 否则结算页变成法律声明. 与「可运营帮助中心」的直觉方案不同, 需要忍住不上 CMS.
