# Architecture Smell Report

**Project:** learn-site
**Scope:** 全项目架构与代码气味扫描
**Date:** 2026-08-24
**Analyzer:** smell skill (Ducc)

---

## Executive Summary

learn-site 是一个 **个人运营的单站点课程学习产品** (学习端 + 管理端 + PHP/Webman 后端),目前处于 SpecKit Phase 5 收尾、Phase 6 起步阶段。代码整体质量**偏高**:项目**严格遵守 Constitution v1.2.0**(think-orm 锁定、镜像 digest 固定、TypeScript strict、Zod 契约优先、deny-wins RBAC),文档齐全(SPEC / PLAN / TASKS / HANDOFF / ADR / 6 份 ADR + 7 个 spec artifacts)。

但扫描发现了 **多个系统级别的架构气味**:
- **契约包零测试** — `packages/contracts` 是 API 信任边界,但完全无单测
- **API 客户端重复** — `apps/web` 和 `apps/admin` 的 `http.ts` ~95% 重复 (token 状态机 + refresh-once + 重试逻辑)
- **API wrapper 函数 100% 复制粘贴** — `apps/web/src/api/learner.ts` 20+ 函数,每个都是 try / parse / throwApi 的相同模板
- **DTO 重复定义** — `PaginatedList` 至少 11 处手写;`Id` / `Timestamp` / 标题/状态等内联上百次
- **apps/web 的 ESLint 配置破损** — 缺 `vue-eslint-parser`,且未关 `vue/no-v-html`,但 web 端的 `CourseDetailView.vue` 又用了 `v-html`,**lint 必挂**
- **API 容器以 root 运行** — 违反 Constitution §V "最小权限"
- **mysql 健康检查的密码 token-split 风险** — `-p${MYSQL_ROOT_PASSWORD}` 单 token 形式
- **后端服务层"半贫血"** — controllers 较薄,但 service 层多个 600+ 行 (`CourseService` 710、`LearningMapService` 606),且混用 ORM 模型 + 裸 `Db::name(...)` + try/catch 容错

属于 **结构合理、但维护性正在被复制粘贴腐蚀** 的状态。ponytail 占位 (`// ponytail:` 注释) 标注了 Phase 6+ 必须清理的"未完成",合规但需要追踪。

## Detailed Findings

### Finding #1: packages/contracts 零测试

- **Category:** Testing
- **Severity:** 🔴 Critical
- **Anti-Pattern:** No Tests at the trust boundary
- **Location:** `packages/contracts/src/*` (23 个 .ts 文件,无 `*.test.ts` / `__tests__/`)
- **Principle Violated:** TDD minimum coverage 80% (Constitution §V)
- **Description:** 这是整个 API 表面唯一的类型信任边界 — 所有 Zod schema 在前后端双端共享,但没有任何 schema parse 测试。`packages/contracts/package.json` 定义了 `"test": "vitest run"`,但没有测试文件,`vitest` 会运行 0 个用例。
- **Evidence:** `ls packages/contracts/src/*.test.ts` 0 命中;`packages/contracts/package.json:20` 存在 vitest script 但无 fixture。
- **Recommendation:** 至少对每个 export schema 加一行 happy-path 测试 (`schema.parse(example).success`)。最高 ROI:`envelope.ts`、`auth.ts`、`catalog.ts`、`learning.ts` (支付相关)。这是单测最便宜的一层,每个 5 行以内。

### Finding #2: apps/web ESLint 配置缺 `vue-eslint-parser`

- **Category:** Tooling
- **Severity:** 🔴 Critical
- **Anti-Pattern:** Inconsistent ESLint config; 工具层不工作
- **Location:** `apps/web/eslint.config.js:10-18` vs `apps/admin/eslint.config.js:10-24`
- **Principle Violated:** Constitution §III 端到端类型安全
- **Description:** admin 端的 ESLint 配置正确地用 `vue-eslint-parser` 包装 `tsparser`,并显式 `off('vue/no-v-html')` 给出 HtmlSanitizer 信任边界的豁免。**web 端没有这套配置**。HANDOFF.md 第 196 行已记录"ESLint 在 .vue 上有**预存在**的 parser 错误 (HomeView 复现,与 Phase 5 无关)"。
- **Evidence:**
  ```js
  // apps/web/eslint.config.js — 缺 parser 链
  // apps/admin/eslint.config.js:10-24 — 有 vue-eslint-parser + 关掉 vue/no-v-html
  ```
- **Recommendation:** 复制 admin 的 parser 链到 web,加 `vue/no-v-html: 'off'` 注释引用 HtmlSanitizer 信任边界。**Phase 5 加完 `CourseDetailView.vue` 用 v-html 后 lint 必挂** — 这不是 nice-to-fix,是阻塞。

### Finding #3: web 端 v-html 与 ESLint 规则冲突

- **Category:** Tooling/Security
- **Severity:** 🔴 Critical
- **Anti-Pattern:** Rule not aligned with intent
- **Location:** `apps/web/src/views/catalog/CourseDetailView.vue` 用 `v-html` 渲染 markdown (HANDOFF 174);但 `apps/web/eslint.config.js` 保留 `vue/no-v-html` 默认规则
- **Principle Violated:** Constitution §III 双端校验
- **Description:** 服务端 `HtmlSanitizer` 是唯一信任边界 (`apps/api/app/support/HtmlSanitizer.php`),前端 `v-html` 是镜像渲染,与 admin 端约定一致。但 web 的 ESLint 没关这条规则 → Phase 5 后 `make test-web` 必挂。
- **Recommendation:** 在 `apps/web/eslint.config.js` 加 `vue/no-v-html: 'off'` + 注释引用 `apps/api/app/support/HtmlSanitizer.php`。**与 Finding #2 一起修**。

### Finding #4: packages/contracts 缺 ESLint 配置

- **Category:** Tooling
- **Severity:** 🔴 Critical
- **Anti-Pattern:** Missing tool config; 工具调用失败
- **Location:** `packages/contracts/package.json:19` (脚本 `lint: eslint src`);目录内无 `eslint.config.js`
- **Principle Violated:** Constitution §V 质量门禁
- **Description:** 根 `package.json` 的 `lint` 脚本是 `pnpm -r run lint`,会下沉到 `packages/contracts`,但 contracts 没有 `eslint.config.js`,`eslint` 会找不到配置退出非零。整个 monorepo lint 阻塞。
- **Recommendation:** 加一份最小 `packages/contracts/eslint.config.js` (用 `@typescript-eslint` 即可,无需 vue)。或者从根脚本移除 contracts lint 子命令,只 lint app。

### Finding #5: http.ts 跨 app 几乎完全重复

- **Category:** Coupling/DRY
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Duplicated Code
- **Location:** `apps/web/src/api/http.ts` 与 `apps/admin/src/api/http.ts`
- **Principle Violated:** DRY
- **Description:** 两个文件 120 行,其中 110 行结构相同 (state 结构略有差异:admin 多 `permissionCodes: string[]`)。token 状态机、refresh-once 单飞、`WeakSet` 防重试、axios 实例 + 拦截器完全一致。
- **Evidence:** diff 仅 6 处不同:`API_BASE`、`AuthState` 多一字段、`setTokens` 多处理一个字段、`hasPermission` / `permissionCodes` 两个新导出、注释。
- **Recommendation:** 抽 `packages/contracts` 或新 `packages/http/` 包,提供 `createHttpClient({ baseUrl, onPair?: (pair) => void })`。约 90 行 → 30 行 × 2 + 60 行共享。

### Finding #6: apps/web/api/learner.ts 函数全部复制粘贴

- **Category:** Code/DRY
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Duplicated Code (模板代码)
- **Location:** `apps/web/src/api/learner.ts:50-454`
- **Description:** 20 个 API wrapper,每个都是
  ```ts
  try {
    const { data } = await http.{verb}(path, ...)
    const parsed = ApiResponse(SomeDTO).parse(data)
    if (!parsed.ok) throw Object.assign(new Error(parsed.error.code), { code: parsed.error.code })
    return parsed.data
  } catch (err) { throwApi(err) }
  ```
- **Recommendation:** 一个 `request<T>(verb, path, body, schema): Promise<T>` 工厂替代。452 行 → 200 行。admin 端同样问题(`apps/admin/src/api/*.ts` 也 200+ 行,内联 Zod 解析)。**最高 ROI 重构**。

### Finding #8: ApiOk/ApiResponse 类型/工厂命名冲突

- **Category:** Naming/Design
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Static Cling — 同名双重绑定
- **Location:** `packages/contracts/src/envelope.ts:5-15, 33-35`
- **Description:**
  ```ts
  export const ApiOk = <T>(data: T) => z.object({...})  // 工厂
  export type ApiOk<T> = { ok: true; data: T; ... }      // 类型
  ```
  消费者 `import { ApiOk }` 拿到的是类型,不是 schema。这种"同名绑定两个东西"会让重构时静默丢失运行时验证。
- **Recommendation:** 工厂改名 `apiOkSchema` 或 `makeApiOk`,类型保留 `ApiOk<T>`。`ApiResponse` 同理。

### Finding #9: 命名后缀混乱

- **Category:** Naming
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Inconsistent Naming
- **Location:** `packages/contracts/src/`
- **Evidence:**
  - `auth.ts`: `PhoneSchema` / `PasswordSchema` (Schema 后缀) vs `LearnerLoginInput` / `TokenPair` (无后缀)
  - `captcha.ts`: `CaptchaChallenge` / `CaptchaAnswer` (无后缀,语义不明)
  - `site.ts`: `SiteIntro` / `SiteProfileUpdateInput` / `SiteProfileUpdatedDTO` (同一域三种风格)
  - `envelope.ts`: 工厂 + type 同名
- **Recommendation:** 明确规约并在 CONTRIBUTING / ADR 中固化。ponytail 取舍:**只修最严重 3 个**:`envelope.ts` 类型冲突、`site.ts` 三种命名、`tokenEnvelope.ts` 应改为 `parseTokenEnvelope` (已经是了) → 与 `parseXxx` parser 模式统一到 `parsers/` 子目录或 `parse*` 函数命名。

### Finding #10: 松散 `z.string()` 替代已存在枚举

- **Category:** Contracts/Correctness
- **Severity:** 🟡 Warning
- **Location:**
  - `learningMap.ts:27` `status: z.string()` (Catalog 已定义 `CourseStatus`)
  - `favorite.ts:10-12` `price_mode` / `status` (Catalog 已定义)

- **Description:** 这些字段在 contract 中失去编译时保证,运行时若后端漂移则前端静默吞错。其中 **`PaymentEnvelopeDTO` 是支付相关** — 最糟的地方最松。

### Finding #11: 后端 service 层过厚

- **Category:** Cohesion
- **Severity:** 🟡 Warning
- **Anti-Pattern:** God Service / Multiple Concerns
- **Location:**
  - `apps/api/app/service/CourseService.php` **710 行** — 同时管 course / chapter / lesson CRUD + publish 校验 + sanitize + 列表过滤 + 数据范围
  - `apps/api/app/service/LearningMapService.php` **606 行**
  - `apps/api/app/service/StaffService.php` **461 行**
  - `apps/api/app/service/ReviewService.php` **341 行**
- **Principle Violated:** SRP (一个类一个变更原因)
- **Description:** `CourseService` 已经把 chapter 和 lesson 也接管了 — 实际上是"课程内容服务"却只叫 CourseService。命名与边界不一致。
- **Recommendation:** 拆三件:`CourseService` (course 本身) + `ChapterService` + `LessonService`。`LearningMapService` 类似拆 map / stage / enrollment。ponytail 评估:目前 Phase 5-6 阶段,代码能跑就先不拆,加 `// ponytail:` 注释标记 Phase 7+ 拆。

### Finding #12: service 层混用 ORM 模型和裸 Db

- **Category:** Cohesion
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Leaky Abstraction
- **Location:** `apps/api/app/service/CourseService.php` — 例:Chapter / Lesson 创建用 ORM (`Chapter::create`),但 listForAdmin 用 `Db::name('courses')` 裸查询构造器,且 `countCourseReferences` 用 `Db::name('course_enrollments')` / `Db::name('orders')`
- **Description:** 同一 service 文件内同时出现 `Course::find($id)` 与 `Db::name('courses')->where(...)`。规则隐式但不统一。
- **Recommendation:** 团队规约 "ORM 模型用于单条 + 简单创建,Db 构造器用于复杂查询 + JOIN",写入 ADR 或 .specify/memory/constitution.md 的补充规约。或者把查询封装进 Repository (`CourseRepository::listForAdmin(...)`)。Phase 7+ 整理。

### Finding #13: API 容器以 root 运行

- **Category:** Security/Docker
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Violated Layer Boundaries (privilege)
- **Location:** `docker/api/Dockerfile:60` — `CMD ["php", "start.php", "start"]` 前无 `USER`
- **Principle Violated:** Constitution §V "最小权限"
- **Description:** Webman 进程作为 root 启动,文件上传 / DB 连接 / Redis 全部 root 权限。最小权限应是 `www-data` 或专用非 root 用户。
- **Recommendation:** Dockerfile 末尾 `RUN useradd -m app` + `USER app`。验证 composer install / runtime 写权限 (named volume 仍由 root 拥有但 app 可写)。

### Finding #14: mysql 健康检查 token-split 风险

- **Category:** Infra
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Robustness
- **Location:** `compose.yaml:31-40`
- **Description:**
  ```yaml
  test: ['CMD', 'mysqladmin', 'ping', '-h', 'localhost', '-u', 'root', '-p${MYSQL_ROOT_PASSWORD}']
  ```
  shell 把 `-p${MYSQL_ROOT_PASSWORD}` 解析为单 token。如果密码含特殊字符 (`!@#$%^&*` 等),会按字面拆分或被 mysqladmin 当 flag。
- **Recommendation:** 改成 `['mysqladmin', 'ping', '-h', 'localhost', '-u', 'root', '-p', '${MYSQL_ROOT_PASSWORD}']` (分两个独立元素)。同样的 pattern 在 `MYSQL_USER`/`MYSQL_PASSWORD` 环境变量中已 OK,因为走的是 mysqld `--initialize-insecure` 阶段。

### Finding #15: root package.json 无 engines

- **Category:** Infra
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Drift risk
- **Location:** `package.json:1-16`, `.npmrc:1`
- **Description:** Compose file pin `node:22.11.0`,但根 package.json 没声明 `engines.node`。`.npmrc` 设 `engine-strict=false` → dev 用 Node 20 会静默生成不同 lockfile。
- **Recommendation:** 加 `"engines": { "node": ">=22.11.0 <23" }` 到根,并设置 `.npmrc` 的 `engine-strict=true`。

### Finding #16: `MYSQL_DATABASE/USER/PASSWORD` 无 required 插值

- **Category:** Infra
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Silent fallback
- **Location:** `compose.yaml:17-20`
- **Description:** 只有 `MYSQL_ROOT_PASSWORD` 用 `${VAR:?set in .env}` 强制要求。`MYSQL_DATABASE` / `USER` / `PASSWORD` 用普通 `${...}`,未设时静默回退空字符串,容器启动后失败但报错位置远离 compose 解析。
- **Recommendation:** 同样改为 `:?set in .env`,fail-fast。

### Finding #17: Makefile health 目标硬端口

- **Category:** Infra
- **Severity:** 🟡 Warning
- **Location:** `Makefile:63` `curl -sf http://127.0.0.1:8787/health`
- **Description:** 与 `API_PORT` 解耦 — 用户改 `.env` 把端口设到 9090,`make health` 仍连 8787。
- **Recommendation:** `curl -sf http://127.0.0.1:${API_PORT:-8787}/health`,或在 `make` 中先 `. ./.env` 一次再展开。ponytail 简化:加一行 `-include .env` 到 Makefile 顶部。

### Finding #18: compose.test.yaml 挂 `.env` 到前端测试镜像

- **Category:** Security/Infra
- **Severity:** 🟡 Warning
- **Anti-Pattern:** Violated Layer Boundaries (privilege)
- **Location:** `compose.test.yaml:57-58`
- **Description:** `frontend-test` 服务 `volumes: ['.:/workspace']` 把整个仓库挂进 node:22-alpine。仓库包含 `.env` (本地 MySQL 密码 / 超级管理员密码)。`api-test` 也拿到 `.env` 但它需要,web 不需要。

### Finding #22: TokenEnvelope 每次调用重建 schema

- **Category:** Performance (微小)
- **Severity:** 🔵 Suggestion
- **Location:** `packages/contracts/src/tokenEnvelope.ts:19-23`
- **Description:**
  ```ts
  export function parseTokenEnvelope(data: unknown): ... {
    const TokenPairWithFlag = TokenPair.extend({...})  // 每次调用新建
    const parsed = ApiResponse(TokenPairWithFlag).safeParse(data)  // 每次调用新建
    ...
  }
  ```
  每次 login / refresh 都重新构建 Zod schema。Zod 内部要 cache,但 extend 和 ApiResponse 都重新调用。
- **Recommendation:** 提为模块级常量:
  ```ts
  const TokenPairWithFlag = TokenPair.extend({
    must_change_password: z.boolean().optional(),
    permission_codes: z.array(z.string()).optional(),
  })
  const TokenPairEnvelope = ApiResponse(TokenPairWithFlag)
  ```
  影响极小但零成本。
